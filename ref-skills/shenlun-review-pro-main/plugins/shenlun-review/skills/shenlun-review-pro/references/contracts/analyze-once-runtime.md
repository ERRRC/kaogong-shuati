# analyze-once 普通解析短契约

本文件是无考生作答时的唯一运行契约。不读源码、Schema、命令帮助、字数命令契约或完整评分契约。

## 执行

1. 将完整原题、本题材料、题面字数约束和当前参考答案一次传入 `analyze-once`，并用 `--output /tmp/shenlun-analysis-receipt-<本轮唯一标识>.json` 保存唯一回执。
2. 根据回执的 `analysis_branch`、`analysis_strategy`、`cards` 和 `reference_route` 一次成稿。
3. 调用一次 `finalize-analysis`。只传回执路径、完整正文；无参考答案时再传正文中逐字出现的示范答案。该入口自动读取完整上下文、校验文风和字数，成功后删除回执。
4. 只发送 `approved_text`，通过后不得追加日志、速记、运行结论或其他说明。

收尾校验通过后不得再手工改写 `approved_text`。若正文发生任何变化，必须重新调用 `finalize-analysis`；用户可见字数只能引用该次最终回执的实际字数，禁止并列展示估算值和旧回执字数。

除固定前缀的 `/tmp` 回执外，不得创建 JSON、正文、辅助脚本或日志，不得单独调用 `check-word-count`，不得搜索方法卡或内部字段。原型未命中或有歧义时，只问用户确认五类题型，不展示工程信息，不改题。取得回执后禁止再次调用 `analyze-once`，不得手工复制、删减或重建校验上下文。第一次收尾失败时统一修正一次；第二次失败即停止。文件不得替代正文；回执有效但收尾失败时直接发送正文。

收尾入口只接受三个字段，不需要再查源码：

```json
{
  "receipt_path": "/tmp/shenlun-analysis-receipt-<本轮唯一标识>.json",
  "text": "完整待发送正文",
  "reference_answer_text": "正文中逐字出现的示范答案"
}
```

无用户参考答案时传 `reference_answer_text`；有用户参考答案时省略该字段，也不重复生成完整答案。禁止向收尾入口传 `output_mode`、`reference_available`、方法字段或自行整理的上下文。

## 输入

```json
{
  "question_text": "完整原题题干",
  "material_text": "本题对应完整材料",
  "min_length": 1000,
  "max_length": 1200,
  "length_unit": "字"
}
```

题面只有上限时只填 `max_length`；题面没有字数限制时可省略。未显式填写时，入口只会保守识别“不超过 N 字”、“不少于 N 字”和“N—M 字”。入口也会从题干中的“满分/总分”或“第X题（N分）”提取分值并透传到回执；识别不到或出现冲突时不猜测。成稿必须保留题面已给分值，只有分值未确认时才写“本次不评分”。

有参考答案时增加：

```json
{
  "reference_answers": [
    {"answer_text": "完整参考答案", "label": "用户提供"}
  ],
  "expected_reference_answer_count": 1
}
```

只能在 `reference_answers` 和 `reference_answer_set` 中选一种。显式填写的 `reference_available` 或参考答案数量与实际输入冲突时，入口必须停止，不得自动修正。

如果只有材料、材料摘要、主题梳理，或文字明确表示题干尚未提供，不能调用解析入口。入口本身也会拒绝缺少真实作答任务的文本，避免把材料摘要中的“概括、分析、建议”等词误判成题干。

## 成稿

先拆题，再讲方法，然后逐点回材料原句，说明该句为什么构成得分点、哪些限定不能丢、如何合并压缩，再讲考场组织，最后说易错点。

- 有参考答案：把它作为重要候选回题干和材料校准；若发现遗漏、拔高、错列或冲突，简明说明“参考答案—材料依据—AI选择及理由”，不静默改写口径。
- 无参考答案：材料独立建点，教学解析后默认给出完整示范答案。
- 方法名、步骤和边界只用 `cards` 中已返回的内容，不再查方法库。
- 题面明确提供分值时必须保留题目分值；题面未给分值时只说“本次不评分”，不得自行估分。
- 不展示原型 ID、卡 ID、命令、门禁、文件路径、日志或运行说明。
