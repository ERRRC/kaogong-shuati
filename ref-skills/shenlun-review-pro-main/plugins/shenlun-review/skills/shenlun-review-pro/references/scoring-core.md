# 评分核心

批改边界依据独立记录于 `scoring-evidence.md`。本文件负责可执行的评分与定档规则；方法卡不得反向制造得分点、关键限定或固定扣分值。

本文件定义层级、权重、证据视图和置信度规则。所有评分必须基于实际材料文本，不得凭模型记忆补充材料内容。本文件不定义命令调用顺序；普通批改的唯一运行规则见 `SKILL.md`。

## 目录

1. 层级定义（含评分算术自检、算术执行护栏、覆盖证据护栏）
2. 默认维度权重
3. 一次编译内的三种证据视图
4. 置信度定级
5. 答案校准规则
6. 质量等级边界

## 1. 层级定义

每个评分维度采用 5 级制：

| 层级 | 代码 | 含义 |
|---|---|---|
| 0 | 缺失/错误 | 未涉及或严重偏离 |
| 1 | 弱 | 有涉及但明显不足或偏离 |
| 2 | 基本 | 基本达标，有明显提升空间 |
| 3 | 良好 | 质量较好，小瑕疵 |
| 4 | 充分 | 质量充分，基本无瑕疵 |

### 统一等级锚点框架

所有维度统一遵循以下可观察行为描述。锚点使用跨题通用的行为描述，不引用任何现有 E2E 材料、用户原句、人物、数字或答案。

| 层级 | 统一锚点 |
|---|---|
| 0 | 缺失、完全错误、任务方向相反，或没有可评分证据 |
| 1 | 少量相关表现，但存在根本缺陷，尚未达到基本任务 |
| 2 | 基本达到，核心方向正确，但覆盖、逻辑、结构或表达存在明显缺口 |
| 3 | 较好达到，核心要求完整，仅有局部缺陷，不影响整体成立 |
| 4 | 充分达到，完整、准确、稳定，且没有影响该维度成立的实质缺陷 |

**相邻档判定边界（必须逐条确认）**：

1. **0 与 1**：是否存在有效表现。有任何可识别的相关表现 → 至少 1；完全无证据或方向相反 → 0。
2. **1 与 2**：是否达到最低基本任务。核心方向正确但缺口明显 → 2；方向相关但有根本缺陷（如大面积遗漏、严重偏题、逻辑断裂）→ 1。
3. **2 与 3**：核心要求是否完整成立。核心要求完整、仅有局部缺陷 → 3；核心要求有缺口（如关键要点遗漏、逻辑环节缺失、结构不完整）→ 2。
4. **3 与 4**：是否仍有实质缺陷。完整、准确、稳定、无实质缺陷 → 4；较好但有可识别的局部缺陷 → 3。

**跨档调整护栏**：

5. 不得因单个轻微问题从 4 直接降到 2。轻微问题最多降到 3；要从 3 降到 2 必须有"核心要求缺口"的独立证据。
6. 不得因存在少量亮点从 1 直接升到 3。少量亮点最多升到 2；要从 2 升到 3 必须有"核心要求完整成立"的独立证据。
7. 证据同时落在两档时，使用较低档并说明缺少的升级条件（写入 `upgrade_condition`）。
8. 每个等级判断必须引用可观察证据（写入 `anchor_evidence`），不得只给结论不给证据。

### 临界档裁决流程

当某维度证据落在两档边界时，必须按以下固定流程裁决：

1. **先写该维度当前已满足的锚点**（`anchor_evidence`：列出已满足的可观察行为）。
2. **再写升入上一档仍缺少的条件**（`upgrade_condition`：1/2/3 档必填）。
3. **裁决规则**：
   - 若证据完整满足高档条件，取高档。
   - 若关键升级条件不明确，取低档。
4. **记录**：临界档必须记录 `borderline_decision`（写明：当前档、目标档、裁决依据、是否取低档）。
5. **防重复扣分**：轻微语言或局部遗漏不得重复影响多个维度。同一问题只能在最直接的维度主扣一次（`deduction_owner` 记录主扣维度）；其他维度如受实质影响，必须说明不同影响机制。
6. **跨两档调整门槛**：若评分者准备跨两档调整（如从 2 到 4，或从 4 到 2），必须列出至少两个独立实质证据；否则只允许调整一档。缺少两个独立证据的跨两档调整视为未通过算术自检，必须先内部修正。

**诊断得分** = `层级 / 4 × 该维度权重`

若提供满分（如 40 分），则：`最终得分 = Σ(层级 / 4 × 权重) / Σ权重 × 满分`，再按“中心值取整规则”取整（见下文“评分算术自检”）。

若无满分，则按 100 分制输出。

字数限制不是题目满分。题面只出现“不超过 150 字/1000 字左右”等字数要求时，仍视为未提供满分，使用 100 分诊断标尺。

### 评分算术自检

输出分数前必须逐项复核：

1. `诊断总分 = Σ(层级 / 4 × 权重)`，不得与分项表相加结果不一致。
2. 未提供满分时，分数中心就是诊断总分按“中心值取整规则”取整后的值；不得把字数限制当满分。
3. 提供满分时，先按满分换算，再按“中心值取整规则”取整。
4. 区间半宽固定为 `题目满分 × 5%/10%/15%`；未提供满分时以 100 为基数。
5. 区间上下界必须由同一个中心值计算，并按 0.5 分精度表达；下界不得小于 0，上界不得超过题目满分。超出时必须截断到有效分数范围。
6. 分项合计、中心值、区间三者必须先内部校正一致，再一次性输出最终值；正式结果中不得保留前后冲突的分数或区间。若前文先出现错误分数、后文再“修正”，视为未通过算术自检。

#### 中心值取整规则

中心值统一按“四舍五入到最近的 0.5 分”取整，边界采用“半数进位”（round half up），不得使用截断、银行家舍入（round half to even）或半数退位。

可执行定义：

```
中心值 = round_half_up(诊断总分 × 2) / 2
```

等价步骤（任一模型按此执行均可得到同一结果）：

1. 将诊断总分乘以 2；
2. 对结果做标准四舍五入取整：小数部分 ≥ 0.5 进位，< 0.5 舍去；
3. 再除以 2。

显式示例：

| 诊断总分 | × 2 | 四舍五入取整 | ÷ 2 = 中心值 |
|---|---|---|---|
| 63.75 | 127.5 | 128 | **64.0** |
| 63.25 | 126.5 | 127 | **63.5** |
| 52.5 | 105.0 | 105 | **52.5** |
| 82.5 | 165.0 | 165 | **82.5** |

边界要点：

- `x.75` 一律进到 `(x+1).0`，不得退到 `x.5`；
- `x.25` 一律进到 `x.5`，不得退到 `x.0`；
- 已落在 0.5 整数倍的值保持不变。

示例：无题目满分、诊断总分 82.5、中置信度时，中心为 82.5，区间为 72.5–92.5；不是按中心值的 10% 展宽。

### 算术执行护栏（输出前硬检查）

以下检查必须在正式输出前逐项执行；任一断言失败，先内部修正，不得把错误值和"修正值"同时输出。

#### 护栏 1：单项得分必须由层级直接计算

每个维度只能执行：`单项诊断得分 = 层级 ÷ 4 × 权重`。不得先凭感觉填写一个连续分数，再反推层级。

对于权重 W，合法单项得分只能来自：

| 层级 | 合法得分 |
|---|---|
| 0 | 0 |
| 1 | 0.25W |
| 2 | 0.50W |
| 3 | 0.75W |
| 4 | 1.00W |

#### 护栏 2：必须逐行复算

正式输出前，对分项评分表每一行执行：

1. 读取该行层级；
2. 读取该行权重；
3. 重新计算 `层级 ÷ 4 × 权重`；
4. 与准备输出的单项得分比较；
5. 任一行不一致，不得继续输出，必须先修正。

不得只检查"模型填写的几个单项得分相加是否等于模型填写的诊断总分"。

#### 护栏 3：必须按正确顺序计算

顺序固定为：

1. 逐行计算单项得分；
2. 对正确单项得分求和；
3. 得到诊断总分；
4. 按 round half up 规则得到中心值；
5. 根据题目满分和置信度计算区间；
6. 最后检查全文只有一套最终结果。

禁止用错误诊断总分继续计算一个形式上自洽的中心值和区间。

#### 护栏 4：输出前算术断言

内部必须同时满足：

- 每行得分 = 层级 ÷ 4 × 权重；
- 分项合计 = 诊断总分；
- 中心值来自正确诊断总分；
- 区间来自同一中心值；
- 正式输出只有一套中心值和区间。

任一断言失败，先内部修正，不得把错误值和"修正值"同时输出。

### 覆盖证据护栏（覆盖映射自检）

以下检查适用于所有产生要点覆盖表的评分输出。

#### 护栏 5：原子要点必须充分拆分

材料中的并列动作、并列措施、不同对象、不同结果，若可以独立得分，应拆成独立原子要点。不得用一行"部分覆盖"掩盖其中一个已覆盖子项和另一个完全遗漏子项。上位概括只能覆盖其概念本身，不能自动覆盖材料列举的独立子做法。

“充分拆分”不等于“越细越好”。拆分后的每一点还必须通过独立得分四问：是否直接回应任务、是否有定位证据、是否与其他点语义独立、是否可单独判定覆盖。概念的例子、子应用、效果展开和证明材料默认并入主要点；不得将同一语义拆成多个遗漏点。

#### 护栏 5A：材料证据边界必须闭合

- `point_text` 中的主体、动作、对象和关系都必须能在 `evidence_text` 或其明确指向的上下文中定位。
- 不得用模型常识补出材料未写的技术、设施、责任主体、因果或反馈链。
- 两段材料分别成立，不代表二者之间的输入输出关系自动成立。关系未明示时应标为争议或可选解释，不得因用户未写而扣分。
- 题干未要求背景、意义或政策依据时，不得把宏观政策论述列为必答点。
- 原子要点池不得参考用户作答建立或补全。
- `independent_scoring: false` 或 `required_or_optional: optional` 的点只是证据、例子或表达加分素材。即使在账本中记录为未覆盖，也不得填写 `deduction_owner` 或 `loss_reason`，不得影响覆盖档位，不得向用户展示为“完全遗漏”。

#### 护栏 6：覆盖状态必须回查用户原文

每个原子要点判定前，必须在用户作答中回查：

- 明确完整出现：完整覆盖或等义表达；
- 出现主体动作但缺数量、对象、范围或关键限定：部分覆盖；
- 完全没有出现：未覆盖；
- 材料没有依据：超出材料。

用户明确写出的内容不得判为未覆盖。缺少关键限定的内容不得无依据判为完整覆盖。

#### 护栏 7：用户原句必须真实、准确

材料要点覆盖表及失分说明中的"用户原句"必须来自用户真实作答。不得：

- 改写后冒充用户原句；
- 引用一句已经包含某要点的话，却声称该要点没有写；
- 把材料原句当成用户原句；
- 为遗漏项虚构用户表达。

对于遗漏项：引用与该类别最接近的用户原句，并明确指出该原句缺少哪个子要点；若用户作答完全没有相关句子，明确写"用户作答未提及"，不得伪造引文。

#### 护栏 8：覆盖数量必须重新统计

覆盖表完成后，必须按表格逐行重新统计：

- 完整覆盖
- 部分覆盖
- 等义表达
- 未覆盖
- 超出材料

统计总数必须等于原子要点总数。如果一个表格行包含多个独立子要点，必须先拆分或分别注明子项状态，不能用单一状态造成统计失真。

#### 护栏 9：扣分说明必须与覆盖表一致

同一个要点在以下位置的状态必须一致：

- 材料要点覆盖表
- 分项评分备注
- 最主要失分
- 修改清单
- 局部示范

不得在覆盖表判"部分覆盖"，又在失分说明中写成"完全未写"；也不得在覆盖表判"完整覆盖"，又以缺失同一内容为由扣分。

#### 护栏 9A：一项问题只有一个主扣维度

- 内容遗漏默认归"要点覆盖/内容覆盖"，不得又因同一遗漏自动降低结论解释、组织表达或语言档位。
- 关系错误归"关系逻辑"；结论无材料支撑归"结论解释"；层次混乱、语句难读才归"组织表达"。
- 若同一问题实质影响第二维度，必须写出与主扣原因不同的可观察证据；否则禁止重复降档。
- "未写满字数上限"本身不是扣分理由。在未低于题面最低字数且表达完整时，不得仅因篇幅短降低组织表达或简洁表达档位。

#### 护栏 9B：大点覆盖 → 子解释联动得分（真实阅卷规则）

真实阅卷中，"大点对了，解释默认给分"（证据 1-5）。当一个核心要点（大点）的关键词或等义表达被用户覆盖时，其下辖的子解释、子展开如果在用户作答的同一句/段中有相关表述，应倾向于判"完整覆盖"或"等义表达"，不因子解释措辞不够精确而单独降为"部分覆盖"。

- 适用条件：大点与子解释之间有明确的"总-分"或"关键词-展开"关系。
- 不适用：大点和子解释是独立并列的得分点（如五个不同压力源）。
- 判定方式：先看大点是否覆盖 → 覆盖则子解释从宽；大点未覆盖 → 子解释独立判定。

#### 护栏 9B-变化：阶段变化优先于细节清单

变化概括题的核心不是把每个阶段的所有动作逐词复述，而是回答每个阶段的“前一种执法/治理方式如何转向后一种方式”。点池应把阶段变化作为核心点，把登记卡、信用评级、系统名称、联合部门等具体动作按材料功能标为展开或准确性证据；只有这些信息本身构成前后变化的关键机制时，才列为关键限定。

- 同一阶段已经写出前后变化方向，并有至少一个材料支持的后续动作或机制时，优先判为核心点已覆盖、展开不足；不得因缺少某一个展开动作直接把整个阶段按低比例部分覆盖。
- 若答案同时覆盖了主要变化方向和大部分具体措施，应采用“完整覆盖/基本展开”或“等义表达/基本展开”，而不是“部分覆盖/简略提及”。
- 材料外词只处理准确性问题：若该阶段的主要变化和其他材料证据仍成立，保留核心覆盖，局部标记材料外或待核对；不得把整阶段归零。
- 只有前后方向缺失、阶段主体被替换，或答案写出的机制与材料相反时，才将阶段核心点判为部分覆盖或未覆盖。

#### 护栏 9C：应用文板块整体赋分（真实阅卷规则）

应用文（贯彻执行）按结构板块整体赋分，不逐词抠分（证据 3-5、3-6、3-7、3-8）。

- `structure_ledger` 中每个板块有 `element_value`（满分值），引擎按 `status × element_value` 自动计算。
- 板块内写了相关内容就给分（如"背景写出原因就得 3 分"），不抠具体写了几个原因。
- 呼吁性文字有即得分，不看怎么呼吁的。
- 内容层面按主体/层面赋分（如学校层面、社会层面），不抠具体做法细节。
- 有的年份结构+得分点混合（证据 3-9、3-10），此时 `structure_ledger` 和 `point_ledger` 同时存在，引擎分别计分后加权合并。
#### 护栏 10：明确写出不得判未覆盖（中性示例）

用户答案明确写出某项核心语义时，不得判"未覆盖"。缺少数字、对象、范围或限定条件时，可判"部分覆盖"，但不得把明确出现的内容判为未覆盖。

**中性示例（不得复用现有 E2E 题面）**：

- 材料：投诉量同比增加 18%。
- 用户：投诉有所增加。
- 判定：至少"部分覆盖"或"等义表达"，**不得判"未覆盖"**。用户已写出"投诉增加"这一核心语义方向，仅缺少 18% 这一具体数值限定。
- 仅当题目明确要求列举具体数值、且该数值本身是独立得分信息时，才可按"部分覆盖"处理；不得因省略数字就判"未覆盖"。

`expression_only` 只能用于没有新增实质语义、关系或得分点的表面改写；一旦二稿新增了核心语义、关系或得分点，不得标 `expression_only`。

### 字数门禁（确定性校验）

字数限制是题面硬约束，必须建立统一、可执行的字数检查。

1. **审题阶段记录**（写入 `analysis-result.constraints`）：
   - `min_length`：下限（题面给区间时取下限；只给上限时为 null）
   - `max_length`：上限（题面"不超过 N 字"时 `max_length = N`，`min_length = null`）
   - `length_unit`：单位，申论默认"字"
2. **解析模式生成完整参考答案时**：
   - 生成前先确定作答字数预算（默认内部规划目标为上限的85%–95%），并建立必保留的材料证据词清单。该区间是为方格布局留余量的训练建议，不是官方统一扣分档位
   - 优先压缩空话、重复和连接词，不得为达到字数而先删可区分得分点的材料主体、动作、对象和特色细节
   - 必须计算正文实际字数（口径见下"字数统计口径"）
   - 实际字数必须处于 `[min_length, max_length]` 内（仅有上限时 `≤ max_length`）
   - 超限或不足不得作为最终参考答案输出；必须自动压缩或补充后重新校验，直到合规
3. **批改和二稿模式**：
   - 必须计算用户正文实际字数
   - 超限或不足必须明确诊断，并影响对应维度（任务符合 / 简洁表达 / 结构 / 题型协议规定维度）
   - 不得把不合字数要求的答案评价为完全合规
4. **Markdown 标题、解释文字、评分表、方法卡引用表不得计入作答正文**。
5. 确定性校验入口：`scripts/review_engine.py check-word-count`（见 SKILL.md 确定性引擎表）。

#### 字数统计口径

- 统计对象：作答正文（用户答案或参考答案的正文部分）
- 计入：中文汉字、中文标点、阿拉伯数字、英文字母，每个字符计 1
- 不计入：Markdown 标题符号（`#`、`##` 等）、Markdown 列表符号（`-`、`1.` 等）、引用符号（`>`）、表格分隔符（`|`）、代码块标记、解释性说明文字、评分表、方法卡引用表、`analysis_id` 等元信息行
- 段落间空行不计入；段内空格计入
- 单位：`length_unit = "字"`（申论默认）

#### 考场方格与文本估算的边界

1. 题面的“不超过N字”、字数区间和答题卡有效作答区是硬约束；正式输出不得超题面上限。
2. 实际纸质答题卡上，标题、称谓、正文、标点、序号、落款等只要写入方格就会占用作答容量；提前换行和段首留空也会减少可用格子。
3. `check-word-count` 对电子文本做确定性字符估算，无法在没有每行格数和手写布局时精确还原纸面占格。因此解析模式要留合理余量，但不得声称电子字符数就是真实答题卡格数。
4. 写出指定答题区域之外的内容可能无法进入有效评阅图像；这与“超一个字固定扣1–2分”不是同一条规则。

#### 不得宣称为全国通用硬规则的经验口径

在用户没有提供当次考试官方评分细则时，以下内容只能作为训练风险提示，不得用于确定性扣分：

- “不超过N字”超一格统一扣1–2分。
- “N字左右”在所有国考、省考中都统一按±10%计分。
- 申发论述950–999、900–949、800–899、低于700各自对应固定扣分或固定档位。
- 超过1250字必然降档，或超过某条红色字数刻度线的文字必然不扫描。只有超出指定有效答题区的内容可按无效作答风险处理。
- “1080–1150”或“上限九成”是官方满分区间。
- 序号必须统一写成 `1.2.3.`，或段尾标点可不占独立方格。

若用户提供某地某年官方细则，可以 `official_override` 仅覆盖对应考试，不外推为其他地区或年份的统一标准。

### 必需格式要素规则（贯彻执行）

贯彻执行题建立并复用 `required_format_elements`，解决"审题说无需落款、批改却因缺落款扣分"的口径不一致问题。

1. **审题阶段**先根据身份、文种、对象和题面要求确定必需格式，写入 `analysis-result.constraints.required_format_elements`。
2. **批改时只允许对缺失的"必需格式要素"扣 `身份文种格式` 分**；不得对未列入 `required_format_elements` 的要素扣格式分。
3. **不得因为内容不充实、背景不足、号召不足或语言问题扣 `身份文种格式` 维度**（这些计入 `内容覆盖` / `目的场景` / `语言语气`）。
4. **情况报告、调研报告等题目若未要求发文对象、称谓或署名**：
   - 一般只要求 `["标题", "正文结构"]`
   - 不得因为没有称谓、落款而扣分
5. **审题、解析、批改和二稿必须复用同一份 `required_format_elements`，不得前后改口**。`grade-once` 内部在评分时会校验必需格式要素与结构账本是否一致；题干未要求的格式要素不得进入扣分。
6. `missing_format_elements`（批改时实际缺失的必需要素，`required_format_elements` 的子集）是唯一允许扣格式分的依据。

### 维度归因与防重复扣分

- `任务符合`只判断是否理解作答对象、任务动词、身份和文种；遗漏材料要点主要计入`要点覆盖`，不得因同一遗漏再次降低`任务符合`。
- 每条失分先确定唯一主维度；只有确实存在相互独立的影响时才可涉及另一维度，并分别说明依据。
- 不得用同一现象在多个维度重复扣分。具体题型协议对维度边界有更细规定时，以协议为准。

## 3. 一次编译内的三种证据视图

以下“材料、作答、校准”是同一次 `grade-once` 编译中的证据分层，不是三次命令、三次材料扫描或三次建池。有参考答案时，校准视图与材料证据在同一份点池中完成，不另建竞争点池。

### 材料遍（Material Pass）

**输入**：仅材料文本（用户作答和参考答案均不参与）。

**产出**：

- **任务档案**：题型识别、核心任务指令、材料主题摘要、关键限定词。
- **原子要点池**：从材料逐段/逐句提取的核心信息点，每点标注来源段落或句子位置；要求覆盖材料全部可采信息，允许多余不遗漏。
- **点池粒度先复核再计分**：同一功能的动作、场景、例子、效果和背景先合并为“主点＋展开”，再拆分真正承担不同任务功能的独立主点。连续叙述的多个动作不当然等于多个独立得分点；不得因点数变多制造虚高，也不得因合并抹掉主点中的关键限定。
- **段落证据索引**：每个原子要点关联的原文证据句（含段落编号或句序）。

材料遍不评价用户作答，不受参考答案引导。材料遍完成后可自查：要点是否覆盖材料所有段落，是否有遗漏或重复。

### 作答遍（Answer Pass）

**输入**：材料文本 + 用户作答文本（参考答案不参与）。

**产出**：

逐原子要点判定覆盖状态：

| 状态 | 含义 |
|---|---|
| 完整覆盖 | 完整呈现该要点，表述准确 |
| 部分覆盖 | 有涉及但不完整或有偏差 |
| 等义表达 | 用不同词汇/句式呈现同一要点 |
| 未覆盖 | 用户作答未涉及该要点 |
| 超出材料 | 作答内容在材料中无依据（标注但不评分） |

结构与表达评价：

- 分段/层次是否清晰
- 语言是否简洁、准确
- 格式是否符合文种要求（贯彻执行题）

### 校准遍（Calibration Pass）

**输入**：用户作答 + 官方答案/评分标准/参考答案。

**校准原则**：

1. **参考答案是校准基准，不是唯一答案**：参考答案的要点覆盖范围用于候选校准；等义但不同措辞的要点不得因措辞差异扣分。
2. **官方评分标准可调整维度权重**：当用户提供官方评分标准时，用官方权重替代默认权重。
3. **参考答案是候选要点集**：不论用户提供的来源是什么，统一作为参考答案候选；与材料遍要点池比对后决定采纳。
4. **无参考答案时**：以材料遍独立要点池为基准，置信度降为中。

#### 参考答案漏点与过拆的固定校准

参考答案参与的是候选校准，不是把参考答案的分条原样变成评分点。发现参考答案与材料不完全一致时，按以下顺序处理：

1. **补漏**：先回到材料做反向查漏。材料明确支持、且能独立回答题干的做法，即使参考答案没有，也要进入候选点池并参与评分；不能因“参考答案未写”而排除。
2. **合并**：再检查参考答案是否把同一功能下的研学、传承、文旅开发、品牌宣传等子动作拔高成独立核心。若它们共同服务于城市农业共生、产业激活或文化保护，应并入主点，或标记为“可补充/展开”，不得与独立的栽培技艺、生态循环等核心点等量硬计。
3. **覆盖**：最后用校准后的点池判断考生。考生写出参考答案遗漏但材料支持的点，应正常计入；未写参考答案中的可补充子动作，只记录为展开不全或可优化，不得机械判为核心点完全缺失。参考答案的措辞差异也不改变等义表达的覆盖。

### 两条正式批改路线

**A. 有参考答案**：以参考答案作为高权重候选骨架，直接回材料核验、合并和补漏。参考答案与材料冲突时保留争议，不强行纳入；参考答案没有但材料明确支持的点仍可计入；用户合理等义表达不得因措辞不同扣分。参考答案来源不改变这条路线。

参考答案的分条数量不是机械点数。与材料核对时，先完成同功能合并和主点/展开区分；参考答案用于查漏和校准，不改变材料支持的独立性判断。

**B. 无参考答案**：只用题干、材料和题型方法卡建立点池，再做一次反向复核：查漏点、查误拆、查误合并、查背景/例子误入、查材料外推断。没有参考答案时，点池语义准确性不确定，正式结果必须使用中或低置信度，并扩大区间；若核心点存在未解决争议，应输出待复核说明，不把争议点当确定性漏点。

方法卡只负责提供找点路径和复核提醒，不能制造材料中不存在的得分点，也不能替代材料证据。

大作文另设 `essay_review`：先判断核心命题、关系在题干中的地位和关系覆盖，再判断分论点逻辑线、材料支撑和模板化风险。只有核心关系仅名义提及、遗漏或曲解，或全文论证线断裂时，才限制为三类文上限；辅助关系缺失通常只限制高档；完全偏题限制为四类文。材料用于印证和支撑考生设计的论点，不要求分论点机械按材料顺序排列；模板风险只有与题目针对性弱、材料支撑弱或论证线断裂同时出现时，才限制高档，单句套话不单独降档。

正式 `by_points` 评分还必须有三份上游回执：通过校验的方法卡选择、点池反向复核结果、整体复核结果。任一缺失，不得输出正式分；点池状态为 `disputed` 时置信度降为低。

**禁止虚构局部分值**：用户没有提供可核验的官方逐点评分细则时，不得声称某个要点、任务组件、段落或逻辑关系“占 X 分”“大约 X–Y 分”或“通常各占一半”。可以用“核心任务”“容易遗漏”“对完整性影响较大”说明重要性，但不得伪造数值分配。外部答案或批改中的分值说法必须标注为参考信息，不得冒充官方细则。

## 3A. 逐点计分模式（v0.4 核心新增）

### 设计原则

真实阅卷的核心是**按点/关键词给分**，不是按维度打等级。v0.5 废掉维度等级制作为算分依据，分数完全由逐点计分 + 分数锚定表决定。维度等级仅保留为输出展示用（如"组织表达：良好"），不参与算分。

### 三种赋分模式（按题型自动选择）

| 题型 | 赋分模式 | 关键词精确匹配 | 等义表达 | 部分覆盖 |
|---|---|---|---|---|
| 归纳概括、提出对策 | keyword（按点/关键词） | 完整覆盖 | 与同义直述同等 | 50% |
| 综合分析 | semantic（按意思） | 完整覆盖 | 与同义直述同等 | 50% |
| 贯彻执行、申发论述 | 整体档位 | 只作内容/材料支撑证据 | 不因句式差异降分 | 不进行小题式逐点相加 |

### 展开度判定

**完整覆盖 ≠ 满分。** 覆盖状态只回答"写了没有"，展开度回答"写得好不好"。两者共同决定得分。

每个 scorable_point 的 `expansion_level` 应主动判定。留空时引擎只作保守 fallback：`keyword_match` 为 80%，`semantic_match` 为 70%，其他为 75%。

| 展开度 | 含义 | 赔率 |
|---|---|---|
| 充分展开 | 作为重点写了，有细节、有分析、有材料证据 | 100% |
| 基本展开 | 写了核心意思，有一定展开但不够充分 | 85% |
| 简略提及 | 写了但一笔带过，缺细节或分析 | 65% |
| 仅列标题 | 只写了关键词或总括词，没展开 | 35% |
| 未提及 | 没写 | 0% |

**判定标准（硬规则）**：

**逐点判定流程（真实阅卷对齐）**：

对每个 scorable_point，按以下顺序判定：

1. **先看写了没有**（coverage_status）：用户答案中是否出现该点的核心语义
2. **再看准不准**（match_type）：是关键词精确匹配还是等义表达
3. **再看好不好**（expansion_level）：展开到什么程度
4. **最后看证据长度**（user_quote 长度）：引用的用户原句是否足够长，还是只写了几个字

**引擎自动校验规则**：
- `coverage_status=完整覆盖` 但 `match_type=no_match` → 引擎自动降为"部分覆盖"
- `coverage_status=完整覆盖` 但忽略标点、序号、空格和 Markdown 后的语义骨架不到 `point_text` 的 40% → 引擎将展开上限降至 75%
- 没有显式 `expansion_level` 时，引擎按 `match_type` 保守推导（keyword→80%，semantic→70%，其他→75%）

**展开度判定细则**：
- 用户答案中对该点有 2 句以上展开（含材料证据、具体做法、因果分析）→ **充分展开**（100%）
- 写出核心功能并有必要动作、对象或限定，但展开不充分 → **基本展开**（85%）
- 只概括核心方向，没有必要落地信息 → **简略提及**（65%）
- 只有上位标签或机制名称，无可判定动作 → **仅列标题**（35%）
- 以上判定必须引用用户原句作为 evidence

**关键区分：关键词 ≠ 展开**
- "加强宣传" → 仅列标题（4 个字，没有说怎么宣传）
- "通过讲座、手册、广播宣传" → 充分展开（有具体方式）
- "相关主体认知不足" → 仅列标题（只写上位判断，没有说明具体表现）
- "相关主体认识不足、积极性不高，并出现具体不当行为" → 充分展开（有具体表现和必要限定）

**所有题型都必须判定展开度。** 归纳概括和提出对策也不例外——"写了关键词但没展开"和"充分展开写了做法细节"不应该拿同样的分。

### 权重倒置惩罚

当 core 点只"简略提及"或"仅列标题"时，即使覆盖率看起来不低，也要降分：

- core + 简略提及 → 赔率降至 70%
- core + 仅列标题 → 赔率降至 50%
- core + 未提及 → 0 分

### 高档门槛

无官方逐点细则时，按引擎内部档位区间给出建议分和置信区间，不宣称某个单点的确定扣分。档位是可复算的内部校准，不是官方全国通用分表。

### 定档制评分（真实考场对齐）

真实阅卷老师不会逐点算术，而是先看整体定几类文，再在档内定分。以下定档表模拟这个过程。

**五档制（20 分题）**

一档（16-18 分）：要点基本全覆盖，展开充分，贴合材料，结构清晰、语言规范；上限按满分 90% 作经验校准。

二档（12-15 分）：核心要点基本齐全，少量遗漏，部分内容展开不足。

三档（8-11 分）：覆盖部分作答方向，大多停留在概括层面，细节缺失、遗漏明显。

四档（4-7 分）：有效要点较少，答案较空洞，与题干契合度较低。

五档（0-3 分）：大面积空白、严重跑题，或只有极少有效内容。

**定档条件**
- 先以经过点池复核的**点值加权有效覆盖率**和核心点有效覆盖率形成初步大档；不能只按完整命中点数量计数。当前内部入档参考线为：一档约 95% 且平均展开度至少 75%，二档约 80% 且平均展开度至少 55%，三档约 40%，四档约 20%，其余进入五档。
- 完整覆盖/等义表达按该点点值计入，部分覆盖按当前题型的基础覆盖赔率计入，未覆盖按零计入
- 平均展开度决定是否够格进入更高一档
- 档内定位由展开度越高越靠近上沿
- 整体复核再检查顺序、逻辑、重复、层次和题目要求的结构；只对实质问题限制档位，不做额外文采加分
- 高档审核还要检查前置词是否能统领后文、归类是否贴近材料逻辑；这里的“前置词”只影响结构识别和档内位置，不是独立得分点。只要后文已写出材料支持的主体、动作、对象和关键限定，缺少前置词或前置词略宽泛不得降低该点覆盖；只有前置词与后文实质矛盾、造成主体/动作/因果关系误判，才限制组织或准确性。核心点若仅简略提及/列标题，仍可计为命中，但只能定位在高档下沿，不能进入高档上沿

逐点实得分已经包含覆盖状态和展开度的扣减。定档只负责确定档位上沿和审核强度，不得再次把部分覆盖点按零计入，也不得用同一处展开不足重复扣分。

**所有分数取整数，不出现 0.5 分。**

**引擎自动执行**：逐点计分的结果被截断到所在档的区间内。

### 分布证据与保守校准（v0.3.65）

目前没有国家公务员局公开的全国申论原始分数分布或逐题扣分表。官方公开材料主要是各类职位的合格分数线、笔试合成方式和进面规则，不能据此反推出每道小题的平均分。网上“40–50分集中”“60分较好”“70分以上较少”等说法，多来自机构文章、考生经验或入围样本，只能作为低置信度的方向证据，不能直接写成全国统计，更不能把整卷百分位套到单题。

因此只采用一项克制的校准：

- 部分覆盖的基础权重统一按 **0.50** 处理。它表示“方向已经写到，但实质信息不完整”的中点，不表示固定半分，也不是官方扣分规则。
- 完整覆盖仍受展开度影响；充分展开可计入 100%，基本/简略/标题式展开分别按 85%/65%/35% 的内部相对率处理；未提及为 0；材料外内容不计入得分点覆盖。
- 定档与逐点得分使用同一部分覆盖口径，避免部分点先被扣一次、再因有效覆盖率不足被重复压低。
- 该校准只影响单题证据换算，不强行制造正态曲线；整卷总分仍须按题型、题目难度、岗位样本和实际作答整体判断。

用户可见结果仍应写成“整体档位＋证据说明＋经验校准后的建议分”，不要声称“国考官方平均分就是某个区间”。

### 档位、经验上限与用户可见分数

申论阅卷的公开资料通常不能提供可复核的逐点扣分表，因此技能将“档位判断”和“分数建议”分开处理：

- **档位/层次**是对作答整体质量的判断。小题看找点、展开、组织和题目要求；应用文看身份、文种功能、内容板块、结构和语气；大作文看立意、关系命题、分论点体系、材料转化和论证线。
- **逐点合计或维度结果**是证据，不是考场真实算术过程。它用于说明写到了什么、缺了什么、哪里展开不足。
- **档位上沿、百分比锚定和保守上限**是无官方细则时的经验校准参数，用于抑制模型普遍偏高、避免“找对几个点就接近满分”，并让建议分更接近常见阅卷分布。它不是官方评分标准，也不表示真实阅卷老师必然按该比例扣分。
- **建议中心值**是结合整体档位、证据结果和经验上限后的模拟结果；**建议区间**用于表达阅卷主观性和证据不确定性。实际考场分数可能落在区间内，也可能因地区、题目难度和阅卷尺度产生浮动。

用户可见输出固定先报“几档/什么层次”及依据，再报建议中心值、建议区间和置信度。推荐表述为：“整体属于二档/二类文，主要依据是……；在缺少官方逐点评分细则的情况下，本题使用了经验校准上限，因此建议中心值为 X 分，建议区间为 A–B 分，实际阅卷可能浮动。”不得把“经验上限”写成“官方最高只能得 X 分”，也不得声称知道某一处必然扣几分。

如果题目同时提供官方评分细则，应优先使用官方档位和分值口径；普通参考答案、评语或范文只能作为参考依据，不能单独证明官方扣分比例。

### 任务边界防偏倚

评分前先锁定原题的任务组件，禁止从考生答案反推任务范围：

- “提出对策/提出建议/改进措施”默认评分组件为 `recommendation`；“针对问题提出对策”中的“问题”是对策对象，不等于要求考生另列问题诊断。
- 只有题干明确要求“梳理问题并提出建议”“分析原因并提出对策”“问题和建议”等复合表达时，才增加 `problem_diagnosis` 或 `cause_analysis` 组件。
- 考生额外写出的背景、问题、原因或意义，可以作为理解对策针对性的辅助证据，但不能因为这些内容写得不完整就自动扣分，也不能把它们自动加入 active required 点池。
- 如果原题不完整、题型无法唯一确定，必须停止正式评分并提示补齐原题；不得改写题干、补造任务词或选择更容易命中的复合原型。

### 整体复核层（v0.6）

小题正式定档前，必须在逐点账本之外整体复核以下问题：

- 点与点之间是否保持材料原有顺序、因果或递进关系；
- 是否把不同层次强行合并，导致阅卷人无法识别独立要点；
- 是否存在同义重复、一个答案表述被重复计入多个点；
- 对策是否真正回应问题，而不是只把问题改写成口号；
- 题目要求“条理清晰/层次分明”时，结构是否可识别。

整体复核只用于确定档位和档内位置，不另加“文采分”或“简洁奖励分”。轻微顺序差异、合理换序和不影响识别的合并不自动扣分；只有逻辑关系被破坏、独立点无法识别或明确重复计分时，才限制档位或修正覆盖判断。

字数紧张时，小题不强制逐条写小标题。题目没有明确要求条理清晰/层次分明时，编号、分条、分号等可识别结构均可；题目明确要求时，必须保留可识别的层次，不等于必须写长标题。

### 分档审核深度

小题先定档，再按档位投入不同审核深度，避免低档答案被无关紧要的表达问题拖得过低，也避免高档答案只因“找到了点”被直接放行：

- **四、五档：minimal**：只核对是否有有效材料覆盖、是否空白或跑题；不对顺序、文采和细小表达作过度扣分。
- **三档：basic**：核对主要遗漏、核心点是否只列标题、展开是否普遍不足，以及是否存在明显重复。
- **二档：standard**：在覆盖和展开之外，核对材料顺序/因果、点与点的层次、重复计分和题目要求的结构。
- **一档：strict**：进一步核对前置词能否统领后文、归类是否贴近材料逻辑、各点是否有有效展开；找点全不等于自动进入一档上沿。

引擎输出 `tier_audit_level` 作为审核提示，不是额外扣分项。应用文和申发论述不使用这套小题分档审核深度：应用文走 `application_review`，申发论述走 `essay_review`。

### 总括点与关键限定

### 前置概括词与实质得分内容分离

申论答案常用“执法更规范”“从粗放到柔性”等前置概括词帮助阅卷人快速定位结构。评分时必须把它与后面的实质内容分开处理：

- 前置概括词、标题词、序号和结构标签本身不独立计分，也不因缺失独立扣分；后文已写出的材料动作、对象、限定和逻辑仍按实际覆盖判断。
- 前置概括词写得宽泛、略有偏差或没有完全概括后文时，优先作为“表达可优化/结构识别提示”，不得把后文已有的核心点改判为未覆盖或低比例覆盖。
- 只有前置词与后文构成实质矛盾，例如主体偷换、把原因写成措施、把结果写成做法、把“从A到B”写成相反方向，或导致整条答案无法识别时，才影响相应的组织/准确性或任务符合维度。
- “只写总括词没有展开”与“总括词不够漂亮但后文展开充分”必须严格区分。前者可能是内容不足，后者不能按标题缺陷扣内容分。

逐条批改应优先呈现“后文实质内容→材料证据→覆盖状态”，再单独提示前置词是否有利于阅卷识别；不得因为前置概括词不精准而重复扣除后文已计入的要点。

材料中的“建立机制/完善体系/加强治理”等总括词，在答案只有该总括词、没有任何具体解释时，不能替代关键动作链。若点池明确列出决定该机制能否落地的关键限定或动作链（例如“编制工作方案—联动实施—闭环落实”），用户只写机制名称而缺少这些限定，判为部分覆盖或高档下沿，不得按完整覆盖处理。若答案已经在后文写出材料支持的具体主体、动作、对象和限定，则前置概括词只按结构标签处理，不得因标签不够精准再次降低后文覆盖。普通例子、效果和背景不自动升级为关键限定。

关键限定必须是会改变该原因、措施或机制是否成立的功能性信息。结果性表述（如“成为领航者”“获得奖项”“位居前列”）、背景事实和普通证明材料不得直接作为考生必须复述的限定。引擎会对“完整覆盖”声明做一次保守语义回查：只有关键限定在用户原句中完全没有语义痕迹时才降为部分覆盖；同义替换、插入词和合理概括不因逐字不同而误降。

`validation_receipt.passed=false` 可能只表示满分门禁、权重倒置或分布复核等软警告，并不等于计算失败。正式结果同时输出 `hard_passed`、`status` 和 `soft_warnings`：只有硬校验失败才阻断计算；`passed_with_warnings` 表示分数已算出但需要人工复核。

**其他普通小题的锚定**（按同一比例框架换算；应用文和大作文另行处理）：
- 10 分题：一档 8-9 分，二档 6-7 分，三档 4-5 分，四档 2-3 分，五档 0-1 分
- 15 分题：一档 12-14 分，二档 9-11 分，三档 6-8 分，四档 3-5 分，五档 0-2 分
- 25 分题：一档 20-23 分，二档 15-19 分，三档 10-14 分，四档 5-9 分，五档 0-4 分
- 35 分题（大作文经验校准）：一类文上限 28 分，二类文上限 24 分，三类文上限 17 分，四类文上限 11 分；与 40 分题采用相同的比例上限（80%/67.5%/47.5%/32.5%），正式分数取整数
- 40 分题（大作文经验校准）：一类文上限 32，二类文上限 27，三类文上限 19，四类文上限 13；正式分数取整数

应用文例外：贯彻执行不直接套用上述小题档位。25 分应用文按任务完成度整体定档：高档上限按满分 90% 作经验校准为 23 分，中高档上限19分，中档上限16分。材料点覆盖汇总为内容完成度证据，但不逐点相加；档位依据身份、文种、目的、内容、结构和语气综合判断，不使用固定局部扣分。格式、OCR 和非必需格式要素不得单独触发降档。

情况简报还要核验“做法+成效”。只写措施、不写工作结果，属于内容覆盖不足；背景不必解释基础概念，材料过程句应概括转写，动态清查要关注其摸清家底、规范合同、清收盘活等作用影响。
### 内部相对权重（无官方细则时）

无官方逐点评分细则时，`point_value` 只是让同一点池可复算的内部相对权重：

1. 先依“直接回应题干、证据独立、语义不重复、可独立判断覆盖”确定 scorable_point，再做归一化权重。
2. 核心任务功能高于支撑展开，但不设全国通用的“核心点固定几分”。
3. optional、merged、excluded 和非独立点不进入正式覆盖计分。
4. 应用文格式只在题干明确要求时参与整体定档，不设通用的格式占比或局部扣分。

用户可见输出不展示这些内部权重，更不得声称“漏某点必然扣 X 分”。只报材料证据、覆盖状态、整体档位和经验校准的建议分。

### 向后兼容

旧输入不带 point_value 时，自动 fallback 到维度等级制（by_dimensions），行为与 v0.3 完全一致。

**校准操作**：

- 重新检查作答遍中标记为"未覆盖"的要点：是否有等义表达被遗漏识别。
- 核对分项评分是否与要点覆盖情况一致。
- 调整分数区间和置信度。

## 4. 置信度定级

| 置信度 | 条件 | 分数区间 |
|---|---|---|
| 高 | 材料完整 + 任务明确 + 官方评分细则完整 + 参考答案与材料证据无明显冲突 | 中心 ± 满分的 5% |
| 中 | 材料完整 + 任务明确，但无完整官方评分细则（包括仅有参考答案） | 中心 ± 满分的 10% |
| 低 | 等义争议 / 多种合理分类 / 参考答案冲突 | 中心 ± 满分的 15% |

**不评分**：材料不完整（缺失页、OCR 不清、关键段落缺失）时，输出"不评分"，不给出低置信度分数。

区间宽度以题目满分为基数；未给满分时按 100 分诊断标尺计算。例如中置信度在 40 分题中为中心值上下 4 分，而不是中心值的 10%。

## 5. 答案校准规则

### 等义判定

满足以下任一条件即为等义，不得因措辞差异扣分：

- 核心语义一致，仅词汇替换
- 表述顺序不同但信息等价
- 概括程度不同但未丢失核心信息

### 参考答案接受边界

当存在参考答案时，先判断其是否构成“可接受答案边界”，再判断是否需要优化。参考答案不是必须逐字复刻的唯一答案；模型临时生成的示范表达更不能反向审判用户提供的参考答案。

将参考答案判为存在硬伤，必须同时有三项证据：

1. 题目要求或材料中存在独立任务功能/独立核心点；
2. 参考答案中没有该功能的语义等价表达；
3. 该功能不能由字数压缩、题干限定、上位概括或上下文合理恢复。

仅缺少题干已经限定的主题词、某个更优动词、具体例子或模型示范中的字面表达，不能直接判为硬伤。若参考答案本身也采用了该压缩方式，且没有官方评分细则证明必须单列，应标记为“可能弱化”或“表达优化”，不直接扣分。

在 100 字以内的极限概括题中，优先判断“动作链和任务功能是否成立”，再评价是否需要补回主题锚点、对象限定或效果词。补词建议可以存在，但补词不等于确定新增得分点。

**正例**：材料“平均审批时长由 20 天压缩至 5 天”，用户写“审批时长大幅压缩”——若当前原子要点考查的是“审批时长显著缩短/效率提升”，核心方向与程度一致，应判等义表达，不能仅因省略数字改判部分覆盖。只有当具体数值本身是独立得分信息、遗漏后改变程度判断，或题目明确要求列举数据时，才按部分覆盖处理。

**总括与子要点边界**：上位总括不能自动覆盖材料中并列、可独立得分的子做法。例如用户只写“完善监管制度”，不能视为覆盖其下未写出的“建立值班轮换台账”；该子要点仍应标为未覆盖。

### 置信区间展宽

- 低置信度（等义争议）：慢审 → 逐条重标 → 比对参考 → 解释争议两侧，给出两侧分数区间。
- 多方参考答案冲突：并列展示差异要点，不强行取中。

### 不输出完整参考稿

默认只输出修改建议和局部示范。仅在用户明确要求"完整参考稿/示范稿"时才输出，且必须标注"示范表达，不是唯一答案"。

## 6. 质量等级边界

| 等级 | 含义 | 是否可用于评分 |
|---|---|---|
| A | 来源可靠、方法可执行、触发条件明确 | 可直接用于讲解与评分 |
| B | 来源基本可靠、方法可执行 | 可用于讲解与评分 |
| C | 来源或执行性存疑 | 仅作检索线索，不直接用于评分 |
| D | 来源不可靠或方法不可执行 | 必须跳过 |

Phase 1 中性核心不涉及方法卡质量等级；Phase 2 启用后按此边界处理。

## 7. 评分锚点证据字段（可选契约字段）

为降低评分波动，`scoring-input.schema.json` / `scoring-result.schema.json` 保留以下可选证据字段。它们服务于引擎内部校验和开发契约，不是普通批改的额外命令链路。

| 字段 | 位置 | 类型 | 要求 | 用途 |
|---|---|---|---|---|
| `anchor_evidence` | `dimensions[].anchor_evidence` | string | 每个维度至少 1 条 | 引用可观察证据支撑当前层级判断 |
| `upgrade_condition` | `dimensions[].upgrade_condition` | string | 层级 1/2/3 必填；层级 0/4 可为空 | 写明升入上一档仍缺少的条件 |
| `borderline_decision` | `dimensions[].borderline_decision` | object/null | 临界档必填 | 记录当前档、目标档、裁决依据、是否取低档 |
| `deduction_owner` | 失分说明/修改清单项 | string | 每条失分必填 | 记录主扣维度，防止同一问题跨维度重复扣分 |

## 7A. 可评分点（scorable_point）定义（v0.3+ 硬约束）

**scorable_point** 是唯一可进入正式覆盖统计、影响要点覆盖档位的点。定义：

```
scorable_point =
    status == "active"
    AND independent_scoring == true
    AND required_or_optional != "optional"
```

**规则**：

- 只有 scorable_point 可以：进入 `coverage_summary`、影响要点覆盖档位、填写 `loss_reason`、填写 `deduction_owner`、出现在"部分得分""完全遗漏""主要失分"中。
- 非独立或可选点（`independent_scoring=false` 或 `required_or_optional=optional`）：只能作为材料证据、例子或可选补充；用于解释主得分点；在用户输出中标为"字数允许时可补充"。不得被称为遗漏，不得影响分数。
- `grade-once` 内部的正式评分必须携带 `point_definitions`（含 status、independent_scoring、required_or_optional）和完整 `score_ledger`，并调用共享的账本验证内核。缺定义、空点池、无 scorable point 或账本无效时一律非0退出。
- 底层 `calculate-score` 只作为开发契约入口保留；`compatibility_mode: "legacy"` 的结果 `formal_score: false`、`legacy_mode: true`，不得进入正式批改、SQLite 写回或用户正式分数展示。
- `point_coverage` 只能包含 scorable points。可选、合并、排除和非独立点放入 `supplementary_evidence`。`supplementary_evidence` 中每项明确 `affects_score: false`、`display_role: "optional_support"`。不得使用"未覆盖"作为可选点的正式展示状态。
- 评分锚点理由中明确把可选点作为降档依据，确定性程序无法安全判断语义时，应要求在 `dimension_evidence` 中绑定 `point_id`。要点覆盖维度的扣分依据只能引用 scorable_point。

**`borderline_decision` 结构**：

```json
{
  "current_level": 2,
  "target_level": 3,
  "took_lower": true,
  "rationale": "核心要求有缺口（关键要点遗漏），不满足3档'核心要求完整'条件"
}
```

**确定性校验**：`scripts/review_engine.py validate-scoring-anchor` 命令校验：
- 每个维度有 `anchor_evidence`（非空字符串）
- 层级 1/2/3 有 `upgrade_condition`（非空字符串）
- 临界档（证据落在两档边界）有 `borderline_decision`
- 跨两档调整（如 draft_1→draft_2 同维度层级变化≥2）必须有至少 2 条独立 `anchor_evidence`

字段不参与算术计算，不影响 `层级÷4×权重` 公式，仅用于约束评分者行为、降低波动。

## 8. 稳定性回归硬规则（v0.3）

以下规则来自第二轮稳定性测试（2026-07-03）的修复。每条规则必须严格执行，不得凭整体印象覆盖。

### E2E-02 综合分析稳定性规则

1. **推测性影响不得成为独立材料得分点**。材料只有"初期出错率上升15%"，"可能影响服务质量"不是材料独立得分点。一稿未写"服务质量"不得扣分。
2. **未要求建议时不扣建议分**。题目未要求建议，不得因未写建议扣任务符合分。
3. **不得要求材料中不存在的深层原因**。如"便民理念"等未在材料中出现的概念不得作为得分要求。
4. **二稿结论和关系逻辑必须依据TaskSpec和账本**。不得凭整体印象波动。

### E2E-03 提出对策稳定性规则

1. **建立问题—建议对应账本**。每条建议必须检查：对应问题、材料依据、主体、动作、对象、落地条件。
2. **"适老化设计"可标合理补充或材料外主张，不得作为材料点**。未在材料中出现的具体设计不得冒充材料得分点。
3. **"主体明确"不能单独升至可行具体3档**。升入3档必须同时满足：大部分对策有明确主体、动作和落地条件。仅有主体明确而缺动作或落地条件 → 2档。
4. **相同账本输入必须得到相同维度等级**。相同得失证据不得因表述差异产生不同档位。

### E2E-04 贯彻执行稳定性规则

1. **"取得一定成效"不得作为语言语气扣分理由**。中性表述不等于语气不当。
2. **required_format_elements四模式一致**。审题、解析、批改、二稿四阶段必须使用同一份格式要素清单。
3. **成效、不足、建议是题面任务元素，不是所有情况报告的固定三段**。不得因未写"成效"段而自动扣结构分。
4. **"知识产权"继续识别为材料外内容**。未在材料中出现的具体知识产权内容不得作为得分点。
5. **内容覆盖、目的场景、结构和语言必须各自依据对应账本证据**。同一问题不得跨维度重复扣分。

无官方逐点细则时，`point_value` 只是同一点池内的归一化相对权重；用户可见输出不得将它说成“漏此点固定扣 X 分”。未覆盖任何材料得分点时不自动赠送“辛苦分”；只按可证据化的覆盖和题型档位计算。
