# 输入门禁

面向用户报告门禁结果时也必须遵守 `output-style.md`：除非用户当前轮明确要求表格，不得用 Markdown 表格列出材料、题号、题型、分值、缺失项或 OCR 疑点。本文内部表格仅用于定义规则，不是回复版式示例。

本文件定义进入题目解析、批改后解析、对照、修改二稿和学情报告前的输入完整性检查。**不通过对应模式的门禁，不得进入该模式或持久化输入。**

整卷 PDF/文档输入默认先完成内部“建卷索引”：只要求能够识别试卷、材料分段和题目元数据，不要求当前就具备某一道题的用户作答，也不进入评分。用户不需要单独选择或调用这个步骤。

单题输入不经过建卷索引：只要当前材料、题目和作答满足对应门禁，直接进入题目解析或批改后解析。

### 纯文字批改的最短路径

当用户已经提供完整题干、对应材料和可直接读取的纯文字作答时，输入门禁只做一次完整性确认，不做格式准备工作。不得因为编号、标点、引号、换行、空格或 Markdown 外壳而要求重新提交，也不得为此调用 OCR、读取图片、查找旧文件或展开引擎调试；这些字符在内容评分前统一归一化。确认题干、材料、作答和参考答案状态后，直接进入唯一的 `grade-once` 入口。

普通小题批改默认只评价纯文字内容：主体、动作、对象、限定、逻辑、任务完成度和材料依据。标点、排版和一般答题格式不作为扣分理由；只有应用文格式、作文结构属于题目任务，或用户明确要求检查格式时，才单独评价。字数限制仍可单独核验，但字数核验不得触发第二套点池或第二次评分。

## 输入角色识别

门禁前先将当前输入区分为：材料、题目要求、用户作答、参考答案、一稿、二稿。

- 优先使用用户的显式标签，如“我的作答”“我的答案”“参考答案”“老师答案”“一稿”“二稿”。
- 用户上传的讲义、笔记或图片中印刷的“参考答案”不得自动视为用户作答。
- 未标注的第三段文本无法确定是用户作答还是参考答案时，只追问“这段是你的作答，还是参考答案？”，不继续评分。
- 识别到完整材料和完整题目后，按 `SKILL.md` 的“先判断任务”路由自动执行；不得再笼统询问用户要审题、解析还是批改。

## 按模式确定必需输入

| 模式 | 必需输入 |
|---|---|
| 审题 | 完整且经核对的材料文字 + 完整题目要求；不要求用户作答 |
| 解析 | 完整且经核对的材料文字 + 完整题目要求 |
| 批改/对照参考答案 | 完整且经核对的材料文字 + 完整题目要求 + 完整用户作答 |
| 修改二稿 | 上述内容 + 可对应的一稿和二稿（同一 analysis_id） |
| 学情报告 | 可读取的真实作答记录与能力档案（SQLite）；不要求当前题目材料 |

只检查当前模式的必需输入。题目解析不要求用户作答；批改后解析必须有用户作答；整卷 PDF/文档承载不要求用户作答但必须能建立题号和材料范围；不得用题目解析模式绕过批改所需的作答门禁。

## 支持的输入格式

| 格式 | 用途 | 处理方式 |
|---|---|---|
| `.txt` / `.md` / `.markdown` | 普通申论材料/作答 | 保留正文和段落 |
| `.html` / `.htm` | 网页剪藏材料 | 标准库解析，移除 script/style/noscript 及隐藏内容；提取后仍需核对完整性 |
| `.json` | 结构化输入 | 读取 text/content/body/material/answer 字段，不把任意对象拼接成正文 |
| `.srt` | 仅限方法资料整理 | 移除序号和时间轴，保留字幕正文；不作为普通申论作答格式 |

图片/PDF 不在脚本内做 OCR，继续由输入门禁要求核对后的文字。

## 门禁检查项

收到用户输入后，逐项检查以下条件：

### 1. 材料文本

- [ ] 材料文本完整呈现（非片段、非截图残留）
- [ ] 段落编号或顺序可追溯
- [ ] 关键数字、年份、人名、地名可辨认
- [ ] 无明显 OCR 错误导致语义不明

### 2. 题目要求

- [ ] 任务指令完整（字数要求、作答身份、文种要求均可确认；不适用项明确记为"无"）
- [ ] 题型可判定（归纳概括/综合分析/提出对策/贯彻执行/申发论述）
- [ ] 字数限制明确

### 2.1 题面约束的二次核验

题号、分值、字数、身份和文种属于会改变解析或评分策略的高风险字段。图片或 OCR 首次识别后，必须对“作答要求”局部复读，并与题干上下文核对。若出现“15字/45字”等数字冲突、主体名称冲突或字形无法确认：

- 只能记录为“待核对”，不得按常识自动修正；
- 可以继续不依赖该字段的材料结构和得分点分析；
- 不得生成最终参考答案、正式评分或声称字数合规；
- 用户确认或可靠文本确认后，才将确认值写入正式题面并重新压缩/评分。

### 3. 用户作答（批改/对照/修改二稿必需）

- [ ] 作答文本完整（非片段、非截断）
- [ ] 作答字数可见或可估算
- [ ] 无明显乱码或 OCR 错误

### 4. 参考答案（可选，但影响置信度）

- [ ] 参考答案来源明确（官方/机构/教师）
- [ ] 参考答案与题目匹配（题号、题型一致）
- [ ] 参考答案完整（非片段）

## 门禁处理

**当前模式的必需项全部通过**：进入对应模式。题目解析只执行共享前置、题型分支和解析输出；批改后解析才进入答案对照、正式评分和确定性校验；对照模式复用已有解析结果，不重复跑完整解析。

整卷输入通过时，只生成 `paper-analysis` 索引并等待题号或可关联答案；不生成所有题目的 `analysis-result`，不调用 `calculate-score`，不写入任何题目的成绩。

参考答案是可选校准材料：有参考答案走一次“参考候选骨架+材料核验补漏”的快速路径，无参考答案才走“完整材料分析+反向查漏复核”。缺失或不完整不阻断评分，但不得把未核对内容当作官方依据；多份参考相互冲突时按低置信度慢速复核处理。

**任一必需项缺失或存疑**：列出缺失项，告知用户：

> 以下信息缺失，暂时无法评分：
> - [缺失项1]
> - [缺失项2]
>
> 请补充后重新提交。

用户坚持评分也不得绕过门禁。材料缺失、OCR 存疑、身份/字数/文种要求无法确认或题型无法判定时，一律输出"暂不评分"；低置信度不能替代输入完整性。

门禁失败后必须停止：不得继续材料遍、作答遍、分项评分、立意判断、局部优缺点诊断或修改建议。可以做的只有列出缺失/疑点、说明未评分，并告诉用户如何补齐。

## 确定性校验门禁（批改模式额外）

通过语义门禁后，普通批改只构造 `references/contracts/grade-once-runtime.md` 规定的紧凑输入并调用一次 `grade-once`。题型原型、方法路由、TaskSpec、analysis-result、score-ledger、账本校验和评分内核由该入口在同一进程内一次完成。不得在它之前或之后另行调用 `validate-task-spec`、`validate-analysis`、`validate-score-ledger` 或 `calculate-score`。

`grade-once` 返回的 `formal_score=true`、`single_compile=true` 且分数一致性检查通过时，才能输出正式建议分。入口首次返回完整错误列表时，只允许在同一份输入中一次修正全部已列问题；第二次仍失败立即停止，不得手算、拆链路或逐字段试错。

## Python 执行失败分类处理

| 退出码 | 含义 | 处理 |
|---|---|---|
| 0 | 成功 | 正常输出 |
| 2 | 输入/格式/schema 错误 | 列出具体错误字段，请求用户或模型修正输入 |
| 3 | 分析/评分一致性失败 | 列出失败的检查项，不得绕过 |
| 4 | SQLite 状态操作失败 | 报告数据库错误，评分仍可输出但状态不写回 |
| 5 | 报告导出失败 | 报告导出失败不影响评分结果 |

## 图片/PDF 入口

图片和 PDF 提取的文本必须经过用户或可靠文本来源核对后方可进入评分与持久化。仅完成 OCR 不等于通过门禁——还需确认：

- OCR 文本无导致语义改变的错误
- 段落顺序正确
- 无遗漏关键段落

其中，数字、主体名称、动作词、因果词和关键限定词属于“可能改变任务或得分”的实质文字，不能以“只是 OCR 排版差异”为由跳过复核。

宿主自动生成的图片描述、主题概括或“基于主题推断”不算材料原文。凡提取结果出现“可能”“推测”“结合主题判断”、虚构统计数据或无法回查页码时，立即废弃该结果。PDF 优先提取嵌入文本；扫描 PDF 和图片需逐页 OCR。未获得可回查的完整文字前，不得报告试卷主题、材料内容或题目答案。

存在未核对的 OCR 疑点时，只列出疑点并请求用户确认，不进入评分，也不写入材料记录、作答记录或其他状态。

## 输出格式

未通过门禁时的输出模板：

```
## 输入检查

### 已识别项
- 题型：[已识别/无法判定]
- 材料段落数：[N 段/无法确认]
- 作答字数：[约 X 字/无法确认]

### 缺失或不确定项
- [具体缺失项及原因]

### 处理方式
[暂不评分；说明需补充或核对的内容]
```
