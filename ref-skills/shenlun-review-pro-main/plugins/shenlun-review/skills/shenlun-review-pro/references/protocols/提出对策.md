# 提出对策协议

本文件只定义该题型的证据、覆盖和定档细节。材料核验、作答映射和参考校准在同一次入口编译中完成；本文件不定义命令调用顺序。

## 题型识别信号

- "请提出解决……的对策/建议/措施"
- "针对……问题，提出可行性建议"
- "如何解决/改善/推进……"
- "请就……提出对策建议"
- 作答要求出现"针对性强、可行、具体"

## 默认维度与权重

| 维度 | 权重 | 说明 |
|---|---|---|
| 任务符合 | 10 | 是否准确把握对策针对的问题和主体 |
| 问题诊断 | 20 | 是否准确识别材料中的问题/障碍 |
| 针对匹配 | 30 | 每条对策是否针对具体问题，不是空泛建议 |
| 可行具体 | 25 | 对策是否具有可操作性、具体明确 |
| 组织表达 | 15 | 结构是否清晰、语言是否得体 |

## 材料遍重点

- 提取材料中的所有问题/障碍/不足
- 提取材料中已有的对策线索（可直接采用或改进）
- 标注问题与对策之间的对应关系
- 标注问题的主体（谁的问题）和范围（影响多大）

## 作答遍重点

- 检查每条对策是否有对应的问题依据
- 评估对策的可操作性（是否具体到执行层面）
- 检查是否有"万金油"对策（放之四海而皆准但无针对性）
- 评估问题诊断是否准确
- 整体复核问题与对策的顺序、逻辑和重复；对策不得只把问题改写成口号
- 题目只要求“如何做/提出对策”时，问题诊断可体现在措施针对性中，不强制单独复述问题。
- 分条措施已经层次清晰时，不得因缺少“总起句”自动扣组织表达分。

## 校准遍重点

- 参考答案的对策是候选集，允许合理补充材料中可推导的对策
- 对策的表述方式可以不同，但核心方向需针对同一问题
- 参考答案中没有的对策，若能从材料问题合理推导，可视为有效补充

## 常见失分模式

| 失分模式 | 典型表现 | 对应维度 |
|---|---|---|
| 对策空泛 | "加强管理""完善制度"等无具体措施 | 可行具体 |
| 问题错判 | 误判材料中的核心问题 | 问题诊断 |
| 对策与问题脱节 | 对策未针对识别出的问题 | 针对匹配 |
| 遗漏问题 | 只针对部分问题提出对策 | 问题诊断/针对匹配 |
| 缺乏执行性 | 对策停留在原则层面，无操作步骤 | 可行具体 |

## 修改建议方向

- 为每条对策找到对应的问题依据
- 将空泛对策细化到具体执行步骤
- 补充遗漏问题的对策
- 删除与材料问题无关的对策
- 确保对策主体明确（谁来做）

## 维度等级锚点表

以下锚点使用跨题通用的可观察行为描述，不引用任何现有 E2E 材料。

### 任务符合（权重 10）

| 层级 | 锚点 |
|---|---|
| 0 | 未回应对策任务，或方向与题目相反 |
| 1 | 涉及对策，但大量内容偏离问题主体或遗漏核心任务维度 |
| 2 | 基本围绕对策任务，但问题梳理不全面或建议维度覆盖不足 |
| 3 | 准确把握对策任务，问题和建议维度基本完整 |
| 4 | 精准把握问题主体、任务维度和对策范围，全面回应 |

### 问题诊断（权重 20）

| 层级 | 锚点 |
|---|---|
| 0 | 未识别任何核心问题，或问题判断完全错误 |
| 1 | 识别少量问题，大面积遗漏核心问题或误判问题性质 |
| 2 | 识别部分核心问题，存在明显遗漏（如整类问题缺失） |
| 3 | 识别大部分核心问题，仅有少量次要问题遗漏 |
| 4 | 全面准确识别所有核心问题，问题性质判断准确 |

### 针对匹配（权重 30）

明确对策与问题是否一一对应。

| 层级 | 锚点 |
|---|---|
| 0 | 对策与问题完全脱节，或大量"万金油"对策 |
| 1 | 少量对策针对具体问题，多数对策空泛或无对应问题 |
| 2 | 部分对策针对具体问题，但存在以下问题之一：缺少关键问题的对策、多条对策针对同一问题而其他问题无对策、对策与问题对应关系不清 |
| 3 | 大部分对策针对具体问题，一一对应关系基本清晰，仅有少量对应不够紧密 |
| 4 | 每条对策精准针对具体问题，一一对应清晰，无空泛对策 |

### 可行具体（权重 25）

明确主体、对象、动作和落地条件；区分材料直接对策与合理反推对策的边界；区分空泛口号与可执行措施。

“主体、对象、动作、落地条件”是判断线索，不是每条措施必须机械写齐的固定槽位。题面已限定作答身份，或上下文已能明确执行主体时，允许省略重复主语。材料未提供资金来源、负责单位或时限时，不得因用户没有虚构这些细节而降档。

**不得**因为措施没有虚构操作细节而机械降档。材料中已有的具体做法（如保险产品、平台名称）被合理引用即视为具体；仅当材料无具体做法且用户也未合理反推时才可扣分。

| 层级 | 锚点 |
|---|---|
| 0 | 对策完全不可行或无任何具体措施 |
| 1 | 对策均为原则性口号（如"加强管理""完善制度"），无主体、无动作、无落地条件 |
| 2 | 部分对策有具体措施，但多数停留在方向层面，缺主体或操作路径 |
| 3 | 大部分对策有明确主体、动作和落地条件，仅有少量对策可更具体 |
| 4 | 全部对策具体可执行，主体明确、动作清晰、落地条件充分 |

### 组织表达（权重 15）

| 层级 | 锚点 |
|---|---|
| 0 | 结构完全混乱，语言不可读 |
| 1 | 有初步结构但问题与对策呼应不清，语言问题严重 |
| 2 | 结构基本清晰（如"问题+建议"），但问题与建议呼应不够紧密或语言存在明显问题 |
| 3 | 结构清晰，问题与建议一一呼应，语言流畅 |
| 4 | 结构严谨，问题与建议精准对应，层次分明，语言精炼 |

## 逐点计分模式（v0.4）

内部点值只用于同一点池的稳定复算，不是官方单点分值或固定扣分表。

提出对策题使用 **keyword（按点/关键词）** 赋分模式。

### 点值分配规则

1. 题干只要求对策时，只建对策任务点；问题和原因只作针对性上下文，不进入 active required 计分点。
2. 只有题干明确要求“问题/原因＋对策”时，才建立对应的复合任务组件。
3. 点值只表达当前点池内的相对重要性；问题与对策的匹配关系整体进入 `针对匹配` 判断，不伪造单点官方分值。

### 关键词匹配规则

- 用户答案中出现材料关键词或等义词 → keyword_match → 满分
- 用户答案用自己的话表达同一意思 → semantic_match → 按等义内容覆盖，不因句式差异单独扣分
- 完全未提及 → no_match → 0 分

### 展开度

提出对策题也必须判定展开度（v0.4 更新）：

**问题诊断侧**（按"具体表现"判定）：
- "相关主体认知不足" → 仅列标题：只写上位判断，没有说明具体表现
- "相关主体认识不足、参与积极性不高" → 基本展开：有具体表现，但关键原因或后果不完整
- "相关主体认识不足、参与积极性不高、缺少正确方法并采取不当做法" → 充分展开：多个具体表现和关键限定均有覆盖

**对策侧**（按"具体方式"判定）：
- "加强宣传" → 仅列标题（35%）：没有说怎么宣传
- "通过讲座和手册宣传" → 基本展开（85%）：有两种方式但不够具体
- "通过技术讲座、发放知识手册、广播宣传等方式" → 充分展开：列出多种具体方式和宣传目标

**引擎自动校验**：过短的语义骨架可触发展开度复核；标点、编号、空格、换行和 Markdown 长度不参与该判断。
