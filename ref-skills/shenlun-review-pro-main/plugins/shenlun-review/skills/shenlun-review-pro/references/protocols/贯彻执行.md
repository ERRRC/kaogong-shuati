# 贯彻执行协议

本文件只定义该题型的证据、覆盖和定档细节。材料核验、作答映射和参考校准在同一次入口编译中完成；本文件不定义命令调用顺序。

## 题型识别信号

- "假如你是……，请以……身份写一份……"
- "请起草/撰写/草拟一份……"
- "公开信/倡议书/讲话稿/调研报告/工作方案/简报/编者按/导言"
- 明确指定文种、身份、发文对象
- 作答要求出现"格式正确、内容具体、语言得体"

## 默认维度与权重

| 维度 | 权重 | 说明 |
|---|---|---|
| 身份文种格式 | 20 | 仅检查指定身份是否准确贯穿，以及该文种要求的标题、称谓、落款等格式要素是否齐全、位置是否合理 |
| 内容覆盖 | 20 | 是否覆盖文种要求的核心内容要素（应用文轻要点重结构） |
| 目的场景 | 20 | 是否准确把握发文目的和应用场景 |
| 结构 | 30 | 结构是否符合文种规范、板块是否完整、层次是否清晰（应用文阅卷重心） |
| 语言语气 | 10 | 语言是否符合身份和文种要求 |

## 材料遍重点

- 提取与发文目的相关的所有事实和数据
- **三类法提取**（依法行政原则）：材料中出现的以下三类内容是重要得分线索：
  1. **法律法规、规章制度、政策文件**——直接引用即为得分点
  2. **领导的说法/看法**（正面形象）——代表政策精神，是得分依据
  3. **成功的做法/经验**——广义的"法则、规律"，是做法类得分点
- 标注发文对象（写给谁）和发文主体（谁来发）
- 提取材料中与文种要求直接相关的信息
- 标注场景限定（时间、地点、事件背景）
- **时间因素**：材料中出现具体日期时，标注为可能的得分点（如事件发生日期、回应日期体现及时性）

## 作答遍重点

- 检查格式是否符合文种规范（标题、称谓、正文结构、落款等）
- 检查身份定位是否贯穿全文
- 评估内容是否覆盖文种要求的核心要素
- 检查语言是否与身份和场景匹配

### 必需格式要素（required_format_elements）

审题阶段根据身份、文种、对象和题面要求确定必需格式，写入 `analysis-result.constraints.required_format_elements`。批改、解析、二稿必须复用同一份。

**常见文种默认必需要素**（题面另有要求时以题面为准）：

| 文种 | 必需格式要素 |
|---|---|
| 情况报告 / 调研报告 | `["标题", "正文结构"]`（一般不要求称谓、发文对象、落款、署名、日期） |
| 公开信 / 倡议书 | `["标题", "称谓", "正文结构", "落款"]` |
| 讲话稿 | `["标题", "称谓", "正文结构"]` |
| 工作方案 | `["标题", "正文结构"]` |

**批改硬规则**：

1. 只允许对缺失的 `required_format_elements` 中的要素扣 `身份文种格式` 分。
2. 不得因为内容不充实、背景不足、号召不足或语言问题扣 `身份文种格式` 维度。
3. 情况报告、调研报告等题目若 `required_format_elements` 不含落款/称谓/署名，缺这些要素**不得扣格式分**。
4. 审题与批改 `required_format_elements` 不一致必须校验失败，不得前后改口。

**维度隔离**：标题、称谓、落款齐全且身份正确时，`身份文种格式`不得因缺少背景说明、内容不够充实或号召力不足而降档。背景/核心事项遗漏计入`内容覆盖`或`目的场景`；段落安排计入`结构`；号召力和语气计入`语言语气`。同一问题不得跨维度重复扣分。

**统一算术规则**：所有维度均采用统一的 `层级 ÷ 4 × 权重` 计算单项得分，不存在任何特殊换算系数。身份文种格式维度的层级和权重同样遵循此公式。

## 校准遍重点

- 参考答案的格式是参照标准，但允许合理变体
- 内容要点的表述方式可不同，但核心要素需覆盖
- 格式错误（如缺少称谓、落款格式错误）是明确扣分项
- 有参考稿时直接以其文种功能和内容板块作为候选骨架，回题干核验身份、对象和目的，回材料核验事实、措施、结果与要求；不再另建一套平行完整内容分析。
- 参考稿的标题、段落顺序、称谓和落款只作为合理样式之一；题面未要求的格式不得因与参考稿不同而扣分。

材料归位后必须形成“最终内容要点清单”：逐条写出可直接落笔的成效、不足、建议或其他题目要求内容，并附材料依据、必要限定和建议对应的不足。只报告各板块数量、发言人归属或大类名称，不算完成解析。

讲解时至少示范三次“材料原话→功能判断→答案表达”：一次成效、一次不足、一次建议。说明“获得支持”为什么是成效，“但/仍/不到位”为什么提示不足，“需要/应/进一步”为什么提示建议。参考答案可以帮助收束表述，但不能替代这些判断过程。

## 应用文专用整体审核

贯彻执行不是小题的“得分点清单”，也不是大作文的论证线评分。正式批改必须单独记录 `application_review`，按以下顺序整体核对：

1. **身份与文种格式**：身份、发文对象、文种和标题/称谓/落款等必需格式是否匹配题面；合理变体不因与参考答案字面不同而扣分。
2. **目的与对象**：全文是否服务于发文目的，是否站在指定身份面向指定对象说话；不能只把材料内容罗列出来。
3. **内容要素**：背景、问题、措施、倡议或要求等题目要求的功能是否齐全；缺内容计入内容覆盖，不重复扣格式分。
4. **结构层次**：是否形成“身份/目的—主体内容—收束”的可识别结构，段落和要素是否便于阅卷快速定位；不强制套用唯一模板。
5. **语言语气**：是否符合公文语体、对象关系和场景；模板句可以作为连接，但空泛套话不能替代具体任务。

应用文允许复用文种结构，不使用申发论述的“模板化风险”规则；只有身份、文种、目的、内容、结构、语气本身出现问题时，才在对应维度体现，不因大作文式反套路判断额外降档。

### 应用文高档上限

应用文先整体定档，再在档内定位。无官方细则时，25 分应用文高档上限按满分 90% 作经验校准为 23 分；存在一项明显但非致命的任务短板时进入中高档，上限按 19 分校准；核心任务失败时进入中档，上限按 16 分校准。不得把某一种文体的局部评语硬编码成固定扣分，也不能把 OCR 错误、非必需落款或轻微表达问题计入档位。

材料点不是应用文的逐点计分表。点池用于确认该文种需要交代的事实、措施、结果或要求，覆盖情况汇总为“内容完成度”，再与身份、文种、对象、目的、结构和语言共同定档。不得因为漏掉一个次要例子就机械扣一档；但核心内容点或整类任务内容缺失，必须限制高档进入。

### 情况简报专项审核

情况简报不能只把材料中的做法逐条罗列成普通小题答案，还要向领导交代工作情况及其结果：

1. 开头应简要交代工作意义或总体情况，不必解释材料中的基础概念；背景过长、重复释义只作表达优化，不单独扩大扣分。
2. “确保公正公开”等过程表述，应优先概括为可核验的工作机制，不宜整句照抄材料。照抄但意思准确，主要影响概括质量，不直接判为内容缺失。
3. “动态清查、摸清家底”不仅是措施标题，还应核验其作用和影响，如明晰资产资源、规范合同、清收债权、推动治理有序等。
4. 情况简报的核心内容至少同时审核“做法”和“成效”。只写做法、明显缺少定性或量化成效时，`content_status`不得判为`complete`，高档分应受限。
5. 材料出现清收、盘活、增收、规范合同等明确数据时，数据不是每项都必须机械照搬；但整类工作成效完全不体现，应判为重要内容遗漏。

## 常见失分模式

| 失分模式 | 典型表现 | 对应维度 |
|---|---|---|
| 格式错误 | 缺少标题/称谓/落款，格式不符合文种 | 身份文种格式 |
| 身份错位 | 未以指定身份行文，语气与身份不符 | 身份文种格式/语言语气 |
| 内容遗漏 | 未覆盖文种要求的核心内容要素 | 内容覆盖 |
| 目的偏离 | 内容未围绕发文目的展开 | 目的场景 |
| 结构混乱 | 段落安排不符合文种规范 | 结构 |

## 修改建议方向

- 对照文种格式要求，修正格式错误
- 确保身份定位贯穿全文
- 补充遗漏的内容要素
- 调整语言语气以匹配身份和场景
- 优化结构层次，确保逻辑清晰

## 维度等级锚点表

以下锚点使用跨题通用的可观察行为描述，不引用任何现有 E2E 材料。

**维度隔离硬规则**：
- 格式维度（`身份文种格式`）只检查 `required_format_elements` 及身份贯穿
- 内容不足不得混入格式维度（计入 `内容覆盖` / `目的场景`）
- 语言问题不得混入结构维度（计入 `语言语气`）
- 不要求的称谓、落款、日期不得扣分

### 身份文种格式（权重 20）

| 层级 | 锚点 |
|---|---|
| 0 | 文种完全错误，或无任何必需格式要素 |
| 1 | 文种正确但多个必需格式要素缺失，或身份完全未贯穿 |
| 2 | 文种正确，部分必需格式要素缺失或身份贯穿不充分 |
| 3 | 文种正确，必需格式要素基本齐全，身份基本贯穿，仅有少量格式瑕疵 |
| 4 | 文种正确，必需格式要素齐全且位置合理，身份准确贯穿全文 |

### 内容覆盖（权重 20）

| 层级 | 锚点 |
|---|---|
| 0 | 几乎未覆盖文种要求的核心内容要素 |
| 1 | 覆盖少量核心要素，大面积遗漏关键内容 |
| 2 | 覆盖部分核心要素，存在明显遗漏（如整类内容缺失） |
| 3 | 覆盖大部分核心要素，仅有少量次要内容遗漏 |
| 4 | 全面覆盖所有核心内容要素，次要内容基本覆盖 |

### 目的场景（权重 20）

| 层级 | 锚点 |
|---|---|
| 0 | 内容与发文目的完全无关，或方向相反 |
| 1 | 少量内容围绕发文目的，大部分偏离 |
| 2 | 基本围绕发文目的，但部分内容偏离或场景把握不准 |
| 3 | 内容准确围绕发文目的，场景把握准确，仅有少量偏移 |
| 4 | 内容精准围绕发文目的，充分把握应用场景 |

### 结构（权重 30）

| 层级 | 锚点 |
|---|---|
| 0 | 结构完全不符合文种规范 |
| 1 | 有初步结构但层次严重混乱 |
| 2 | 结构基本符合文种规范，但层次不够清晰或段落安排不当 |
| 3 | 结构符合文种规范，层次清晰，仅有少量段落安排可优化 |
| 4 | 结构严谨符合文种规范，层次分明，逻辑递进清晰 |

### 语言语气（权重 10）

| 层级 | 锚点 |
|---|---|
| 0 | 语言完全不符合身份和文种，或严重语病 |
| 1 | 语言与身份/文种明显不符，或大量语病 |
| 2 | 语言基本符合身份和文种，但存在语气不当或部分表达问题 |
| 3 | 语言符合身份和文种要求，语气得体，仅有少量表达可优化 |
| 4 | 语言精准符合身份和文种，语气恰当，表达规范 |

## 应用文结构赋分规则（v0.4，基于真实阅卷证据）

应用文阅卷"轻要点重结构"（证据 3-1、3-2）。以下规则适用于所有贯彻执行题。

### 板块整体评价

应用文按板块整体赋分，不逐词抠分：

- **背景/原因板块**：写出原因就得分，不抠写了几个原因（证据 3-5）
- **问题描述板块**：写了几行问题就作为整体得分，不会逐个问题 0.5 分（证据 3-6）
- **呼吁/结尾板块**：题目要求时检查是否完成呼吁与目的，不伪造固定分值（证据 3-7）
- **内容主体板块**：按主体/层面赋分（学校层面、社会层面），不抠具体做法细节（证据 3-8）

### 格式检查边界

只有题干或文种任务明确要求标题、称谓、落款等格式时才检查；没有要求的格式要素不进入失分。

### 结构+得分点混合模式

有的年份应用文是"结构分+得分点"混合（证据 3-9、3-10）：

- 结构分：板块是否存在（如"开头介绍""前世""今生""结尾呼吁"）
- 得分点：板块内的具体信息（如"缸窑的资源条件好"）
- 两者同时计分，不互相替代

### 时间因素

应用文中时间因素可能是得分点（如烂菜叶案例：七月一号发生，七月三号回应体现及时性）。材料中出现具体日期时，应在作答中体现。

无官方逐点细则时，只按题干要求、内容完成度、场景目的、结构和语气做档位判断，不将经验百分比或案例分值写成固定扣分表。
