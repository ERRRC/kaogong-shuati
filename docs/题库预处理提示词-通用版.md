# 考公题库预处理提示词（通用版 v2）

> 用法：把题库文件（PDF/扫描件/图片）发给执行 Agent，同时粘贴下文。本提示词自包含，不依赖任何仓库路径，手机/电脑均可执行。
> v2 修订（2026-08-29，来自 600 题库实测）：新增文件类型分诊、选项截断自修复、硬性验收门槛、可执行的核对方法、备份纪律。

````text
# 任务：把一份考公题库预处理成标准 JSON

我正在把一份题库导入我的刷题 App 的「自定义题库」功能，需要你先把它整理成 App 能识别的标准 JSON。你不用知道 App 的实现，所有约定都在本提示词内，你只需按此格式交付。

## 一、输入与文件类型分诊（必须先做）

- 我会提供题库文件（可能是 PDF、扫描件、分页图片，或可直接复制的文字，以实际拿到的为准）。
- 第一步先判断**文件类型**，处理路径完全不同：
  1. **标准题库**（有明确题号、选项、答案、解析）：按第二~五节处理。
  2. **笔记/讲义型**（词汇课、方法论笔记，题目以「例题N」「例N」形式嵌在正文里，答案可能集中在卷尾速查表）：不要强行套题库结构。按「例题」标题切题，答案从速查表按例号配对；配不到答案的条目照常收录并标 "failed": true。交付说明里必须注明「笔记型」。
  3. 判断依据：统计文中「选项行数」（以 A./A．开头的行）与「题号行数」（以 1. / 第1题 开头的行）。两者都接近 0 但例题标记密集 → 笔记型。
- 再判断文字能否直接复制：
  - 文本型（能复制）：直接从文本层读取原文，**不要 OCR**，避免二次误差。
  - 扫描型（纯图片）：把每一页渲染成图片，逐页用你的识图/OCR 能力转成文字，再合并处理。
- 表格/多栏版式的页面，必须按**视觉行**（同一行 y 坐标内的文字从左到右拼接）重组文本，不要按内容流顺序拼接，否则表格行会错位。
- 如果拿到的是图片序列（手机拍摄、截图），按文件名/顺序编号当作页顺序处理。
- 文件大就分页逐步处理，最后合并，不允许跳过或简化。

## 二、目标格式（输出一个 UTF-8 编码的 JSON 文件，文件名用题库中文名，如「2025省考判断推理600题.json」）

```json
{
  "source": "原始文件名",
  "count": 600,
  "questions": [
    {
      "qnum": 115,
      "prompt": "题干原文……",
      "material": "材料题共用材料，无材料则为空字符串",
      "options": ["A. ……", "B. ……", "C. ……", "D. ……"],
      "answer": "C",
      "analysis": "解析原文……"
    }
  ]
}
```

## 三、逐字段规则

- `source`：原始文件的完整文件名。
- `count`：与 questions 实际条数完全一致。
- `qnum`：原文题号（如 115），保留原文编号；确实没有编号可省略该字段。
- `prompt`：题干原文一字不改，保留数字、公式、上下标、单位。
- `material`：材料题（如资料分析）的共用材料填进每一道相关题；该题没有材料就填 `""`，不要省略字段。
- `options`：每项以「A. 」「B. 」开头并原文照抄；选项多于 4 个（E/F/G/H）正常支持；判断题原文若没列选项，`options` 留空数组 `[]`。
- `answer`：单选取「C」这种单字母；多选取「AB」（大写）；判断/对错题写「正确」「错误」（与题干用词一致）。**只能在原文明确给出答案时填写**。
- `analysis`：解析原文完整保留；同一题有多份解析（不同来源）时按原顺序拼接保留；缺失就填 `""`，绝不编造。解析不得以「与总结」这类题头残渣开头。
- 图形题选项是图片、无法转文字时：选项占位写「A. A」「B. B」「C. C」「D. D」四格，并给该题加 `"image_missing": true`。

## 四、处理纪律（最重要，违反即返工）

1. 不增删、不改写、不翻译题干/选项/解析，不压缩字数。
2. **找不到答案的题不许猜**——标 `"failed": true` 保留下来；答案解析对不上的题同理。主观题（无选项、无标准答案）也照此处理：`options: []`、`answer: ""`、标 `failed: true`。
3. **选项截断是高发缺陷**：长选项跨行/跨页时，选项文本会被换行切开、下一个字母标记在续行里。切分选项必须按「字母标记在原文流中的位置」切，而不是按行切；切出来不足 4 项（判断题除外）或答案字母不在选项集内时，必须回原文定位该题题干、截到下一题号/解析区边界、按 A→B→C→D 顺序重新扫描字母标记找回缺失项；实在找不回就标 `failed: true` 并列出题号。
4. **解析区与题目区分开的排版**（题在正文、解析集中在卷尾按题号顺序排列）：解析块按文档顺序与题目一一对应；回收解析时用「解析块内的答案字母 === 该题答案字母」做对位校验，不一致就不挂，宁可空着。
5. 完全重复的题去掉；题干相同但选项或材料不同的题保留（那通常是截断残体，按第 3 条修复后去重）。
6. 双栏、跨页、题号乱序等排版问题：以题号为线索重组；题号丢失的按上下文判断归属，仍无法确定的标 `failed`。
7. 材料归属拿不准时（一页材料对应多题）：宁可把材料重复填进每题，也不要漏填。
8. **覆盖旧产物前先备份**（复制一份 .bak 或 .prev.json）。

## 五、交付前自检（硬性门槛，逐条跑）

1. JSON 解析合法、UTF-8；五字段齐全不得省略（无内容处用 `""` / `[]`）。
2. `count` 与 questions 实际条数一致。
3. **逐题校验答案合法性**（不是抽查）：每个非 failed 题的 answer 字母必须能在该题选项的字母集合里找到（判断题用语一致即可）。任何一题不满足 → 回第 4 节第 3 条修复，修不回就标 failed。
4. 客观题选项数 < 4（判断题除外）的全部列出，逐题回原文确认是「本来就 3 项」还是「截断」，截断必须修复。
5. 与原文核对的方法（避免误报）：题干+选项 与 解析**分开**核对；对比前先去除所有空白字符、统一全角/半角标点；图题允许题干与选项之间存在图注文字。随机抽 10~20 题，题干前 20 字必须能在原文命中。
6. 按题干前 24 字做模糊查重，列出疑似重复组人工裁决。
7. 交付时附报告：文件类型、总题数、去重数、failed 数、image_missing 数、修复的截断题数、抽样核对结果。
8. 以 .json 文件形式交付；若无法传文件，就把完整 JSON 内容原样输出（不要截断、不要省略）。
````

## 配套仓库工具（在本机执行时可用，提示词本体不依赖它们）

| 工具 | 用途 |
|---|---|
| `node pdf-work/recon.mjs <pdf>` | 侦察：页数、扫描页、选项行、答案/解析密度 |
| `node pdf-work/run-import-protocol.mjs <pdf> [sample\|full] [maxQ]` | 主解析：文本层提取 → 规则解析 → 截断自修复 → 解析区乱挂回收 → 硬门槛 → `parsed/<名>.json`（自动备份旧产物）；笔记特征命中时自动与笔记提取器按可判分题数竞争路由 |
| `node pdf-work/verify-json.mjs <json> [pages.txt]` | 验收：count 一致 / 五字段 / 逐题答案合法 / 短选项 / 模糊重复 / 原文命中，退出码 0/1 |
