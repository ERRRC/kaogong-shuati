## 三、根因归纳

**问题 A：「搜考公要翻很多页」（排序埋没）**

1. 大词的排名 = 文本相关性 × 流行度；前 100 名被万星仓库垄断，我们 6★/0 watcher 无竞争力。
2. 我们唯一有效的文本是 description，而它是一段 170 字长句、关键词密度低，在 200–1000 名区间（0 星仓库靠短语密度竞争的区间）也排不进去。
3. 仓库名、Topics 两个高权重字段完全空白。
4. README 不参与默认搜索 —— 写得再好也不影响"考公"这个入口。
5. 2 周未推送，丢"最近更新"分。

**问题 B：「没钱考什么公 搜不到」（关键词字段缺失 + 规则限制）**

1. GitHub 仓库名的字符集不允许中文 —— 中文品牌名**永远不可能**成为仓库名或出现在名字字段。
2. 这个中文名在 description 和 README 里也一次都没出现 → GitHub 全站 0 命中。
3. 只有英文谐音 `no-money-no-shore`，而中文用户不会去搜英文谐音。

**问题 C：拼音入口缺席**（叠加问题）

1. 名称/描述里没有 kaogong / gongkao / xingce / shenlun 任何一个词。
2. 拼音查询是 GitHub 上**唯一分词可靠**的入口（词级精确匹配，不像中文那样字符级乱匹配），却完全没利用。

## 四、整改计划

### P0 — 元数据（当天完成，零风险，直接改变可检索性）

**P0-1 重写 description**（GitHub 仓库页右上 About → Description）
目标：短、关键词前置、中英拼音混排、把中文品牌名写进去（这是唯一能搜到中文名的字段）。

建议文案（约 150 字符）：

```
考公刷题 App（公考/kaogong/gongkao）：行测 xingce · 申论 shenlun · 事业单位 · 错题本 · AI 解析。零依赖 Node.js + SQLite 题库，Web + Android(Capacitor)。中文名"没钱考什么公"。
```

要点：
- `考公刷题` 放在最前面（现在是 `考公刷题全栈应用（行测/申论/事业编）：…`，可用但密度低）；
- 补上目前为 0 的词：`公考`、`事业单位`、`kaogong`、`gongkao`、`xingce`、`shenlun`、`没钱考什么公`；
- 总长压到 ~150 字符以内，提高关键词密度（BM25 长度归一化）；
- "零依赖 Node.js + SQLite" 这类技术卖点保留但后置。

**P0-2 添加 Topics**（About 齿轮 → Topics，≤20 个，只能小写 ASCII）

建议：`kaogong` `gongkao` `xingce` `shenlun` `civil-service-exam` `exam-prep` `question-bank` `study-app` `offline-first` `nodejs` `sqlite` `capacitor` `android` `pwa` `ai-agent` `llm` `self-hosted` `education`

价值：`topic:kaogong` 全站只有 7 个仓库，加进去几乎必然出现在 topic 页面前列（topic 页是稳定的发现入口，且不依赖星标）。

**P0-3 加 License**（需决策，见下）

**P0-4 修正语言标签**：新增 `.gitattributes`

**P0-5 推送积压提交**：本地 `b29b769`（09-05）未推送 + 工作区未提交改动 → push 后 `pushed_at` 变新。

**P0-6 README 补关键词行**（次要）：README 不影响"考公"入口的排名，但影响 `in:readme` 检索和**站外搜索引擎**（Google/百度收录的是页面正文）。建议在标题下加一行：

```
> 中文名：没钱考什么公 · 关键词：考公 / 公考 / 行测 / 申论 / 事业单位 / kaogong / gongkao / xingce / shenlun
```

### P1 — 内容与分发（真正决定"能不能被翻到"的是星标）

**P1-1 发一个 GitHub Release**：挂上 APK + release notes。搜索结果点进来的人能看到"活跃、可直接下载"。

**P1-2 站外导流换星标**：你已有 200–300 名离线 APK 用户 —— 这是最现实的星标来源。知乎 / 小红书 / V2EX / 掘金 / B站 / 考公 QQ、微信群，一条"开源了，求 star"的推送通常就能拿到几十星。**星标是"考公"大词前 100 名的硬门槛，没有捷径。**

**P1-3 对外露出补齐**：README 加 stars/license/release/语言 徽章；APK 分发文案里写清 GitHub 搜索词（"GitHub 搜 考公刷题 或 kaogong"）。

**P1-4 建项目主页（GitHub Pages）**：`<title>` 用「没钱考什么公」—— 仓库名做不到的事，网页标题能做到（Google/百度可检索）。可直接复用现有 Web 端。

**P1-5（可选，待观察后决定）重命名仓库**：`no-money-no-shore` → 例如 `kaogong-shuati`。
- 收益：名称字段权重最高，且拼音查询是可靠入口 → 改名后 `kaogong` 查询基本能进前几名；
- 成本：品牌 URL 变化（GitHub 会自动 301 旧链接，星标保留，风险低）；
- 建议：先做 P0 观察 1–2 周排名变化，仍不理想再改名。

**P1-6 提交到 awesome 列表 / topic 页**：加完 topics 自动进入 `github.com/topics/kaogong`；再找中文 awesome 列表（注意 license 是前提）。

### P2 — 长期

- 保持稳定 push/release 节奏（更新频率是排序信号之一）；
- 写 1–2 篇技术文章（"零依赖 Node.js 做考公刷题 App"）带仓库链接，外链提升站外搜索权重；
- 3 个月后复测"考公"大词排名（星标涨到几百后才有机会进首页）。

### 需你拍板的两件事

1. **License 选哪个？** 现在无 license = 保留所有权利，会被 `license:*` 筛选和多数 awesome list 排除。
   - `MIT`：传播最大化，但允许商用 —— 与 README 里"请勿商用"表述冲突；
   - `PolyForm Noncommercial 1.0.0`：与"请勿商用"一致，但不会被主流 awesome list 接受；
   - `GPL-3.0`：防止闭源商用 fork，兼容性较好。
   建议：若目标是让人找到、用起来 → `MIT`（并在 README 说明"题库数据不含，仅代码开源，请勿商用数据"）。
2. **要不要改仓库名？**（见 P1-5，建议先观察再定）
