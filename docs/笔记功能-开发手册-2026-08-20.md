# 「笔记」功能开发手册（AI → AI 交接）

> 生成时间：2026-08-20 · 适用版本：v1.33（versionCode 34）· 工作区：`D:\nomoneynowork`
> 阅读对象：后续接手开发的其他 AI agents。本文档只讲「笔记」功能这一次的改动，项目全貌见 `HANDOFF.md` / `README.md`。

---

## 1. 一句话功能

用户可在**任意题目**（含自定义题库）上添加/修改/删除笔记；笔记统一汇入首页快捷入口「笔记」模块，支持列表浏览、点击重做、随机练习。同时按要求**精简了做题页底部操作条**（删除上一题/下一题）。

## 2. 需求要点（用户确认的交互规则）

1. **一题一笔记**：重复添加 = 更新内容（upsert），不做多笔记/版本历史
2. **笔记可修改**：添加后不是终点，做题中/成绩页点「查看笔记」可随时改
3. **做题页按钮状态切换**：该题已有笔记 → 显示「查看笔记」（绿色高亮）；无笔记 → 显示「添加笔记」
4. **做题页底部操作条精简**：删除「上一题」「下一题」，从左到右只保留 **添加笔记（/查看笔记）｜ 查看解析 ｜ 交卷**
5. **添加笔记的 4 个入口**：做题页操作条、成绩与解析页（每题卡片）、背题模式反馈框、笔记列表页（编辑按钮）
6. **笔记模块页**：快捷入口进入，列表展示（题面摘要 + 笔记预览 + 时间），点击重做，可随机练习（抽 10-15 题）
7. **视觉风格一致**：图标/色板/按钮高亮/弹层全部复用现有设计语言

## 3. 数据设计

### 3.1 Web 端（practice.db 新表，server.mjs 建表）

```sql
CREATE TABLE IF NOT EXISTS notes (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id TEXT NOT NULL UNIQUE,   -- TEXT：天然支持 custom- 前缀自定义题
  subject TEXT DEFAULT '',
  chapter TEXT DEFAULT '',
  note TEXT DEFAULT '',               -- 笔记内容
  created_at TEXT DEFAULT (datetime('now','localtime')),
  updated_at TEXT DEFAULT (datetime('now','localtime'))
);
```

### 3.2 App 端（IndexedDB，public/idb-store.js）

- `STORES` 数组追加 `'notes'`（DEFAULT_VERSION 2 → 3，onupgradeneeded 自动建表）
- `rowKey()` 加分支：`notes` 与 `favorites` 相同，key = `String(question_id)`
- 单条记录：`{ question_id, subject, chapter, note, created_at, updated_at }`

## 4. API 设计（双端同构，3 路由）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/notes?limit=&offset=` | 列表 `{list,total,offset,limit,hasMore}`；按 `COALESCE(updated_at,created_at) DESC` 排序；list 项含 `{questionId, subject, chapter, note, time, content, type}`；题面联表（custom- 前缀走 custom_questions，与收藏同构，80 字截断） |
| POST | `/api/notes` | body `{questionId, subject, chapter, note}`；**upsert**：`ON CONFLICT(question_id) DO UPDATE SET note/subject/chapter/updated_at` |
| DELETE | `/api/notes` | body `{questionId}` 删除 |

实现位置：
- Web 端：`server.mjs`（路由紧跟 `/api/favorites` 之后，约 1560 行）
- App 端：`public/local-handler.js`（3 路由）+ `public/local-api.js`（`notes()` / `upsertNote()` / `deleteNote()` / `noteIds()`）

## 8. 关键踩坑（下一位必读）

1. **node:sqlite number 绑 TEXT 列会浮点化**：`INSERT ... .run(2137304)` 存成 `"2137304.0"`，前端 `questionId` 变 `"2137304.0"` 匹配不上。**必须 `String(questionId)` 绑定**（server.mjs POST/DELETE 已修）。
2. **测试残留污染**：浏览器 e2e 会写真实 practice.db——脚本开头先 API DELETE 清空 notes 再测，测完验证 total=0。
3. **漏答确认弹层**：全未答交卷会弹 `#btn-force-submit` 确认框，自动化测试要处理。
4. **导航栈语义**：`navStack` 是「来源页」栈，`enterQuiz` 不入栈；快进入模式（随机练习）返回靠入栈层数。笔记随机练习入栈 2 层才正确回列表。
5. **双端同构铁律**：`lib/*.mjs` ↔ `public/lib/*.js`、`server.mjs` ↔ `local-handler.js` 必须同步改；改 `public/` 后手动同步到 `app/android/app/src/main/assets/public/` 再打包（本次 5 个文件：app.js / local-handler.js / local-api.js / idb-store.js / style.css）。

## 9. 打包（v1.32 / versionCode 33）——踩坑记录

- **`npx cap sync android` 本机永久卡死**（npx 网络检查 + spawn 问题，>7 分钟零输出），本地 CLI 同样卡 → **放弃 cap sync，改手动同步**：
  1. `cp public/{...5 个文件} app/android/app/src/main/assets/public/`
  2. 若 `app/android/capacitor-cordova-android-plugins/` 缺失：解压 `app/node_modules/@capacitor/cli/assets/capacitor-cordova-android-plugins.tar.gz`（**不要 `--strip-components`**，tar 顶层即 build.gradle + src/）+ 手工写 `cordova.variables.gradle`（模板见 cli 源码 `dist/android/update.js` `handleCordovaPluginsGradle`，minSdk=22）+ build.gradle 的 `// PLUGIN GRADLE EXTENSIONS START` 后补 `apply from: "cordova.variables.gradle"`

## 12. 后置完善（2026-08-21，v1.33 / versionCode 34）

接手后审计发现的 4 处问题与修复（改动文件：server.mjs / local-handler.js / local-api.js / app.js / test-local-api.mjs / build.gradle）：

1. **App 端列表时间显示为原始毫秒时间戳**（如 `1784662337000`）→ `local-api.js` 新增 `fmtDT()`，笔记/收藏/错题/最近记录统一格式化为 `YYYY-MM-DD HH:mm`（与 Web 端 SQLite datetime 展示一致）。
2. **笔记超过 200 条时兜底失效 + 有覆盖旧笔记的数据风险**：原兜底只重拉同一个前 200 页，更早的笔记查不到，弹层会误判「添加笔记」，用户保存即覆盖旧笔记。→ 新增 `GET /api/notes?qid=` 单条权威查询（server.mjs + local-handler.js + local-api.js 三端同构）；`openNoteSheet` 缓存未命中时按 qid 补查，查到则把弹层升级为「查看笔记」（标题/预填/删除按钮）并同步做题页按钮状态。
3. **笔记列表页「编辑」保存后列表预览不刷新、弹层删除后计数/加载更多文案不更新** → `noteItemEl` 加 `data-note-item` 标记；新增 `refreshNoteListItem()`（定向更新预览，不整体重渲染）与 `removeNoteFromList()`（删除条目 + 同步计数 + 空态）；弹层保存/删除在 `store.state.view === 'notes'` 时联动调用。
4. **服务端 POST 无空值/长度校验** → server.mjs 与 upsertNote 双端对齐：`trim().slice(0, 500)`（与前端 maxlength 一致），空内容返回 400「笔记内容不能为空」。

验证：`node test-local-api.mjs` 29/29（新增 5 条：qid 命中/未命中/时间格式/空内容拦截/超长截断）；server 路由 round-trip（POST→?qid= 命中与未命中→空内容 400→DELETE→无残留）通过；`npm run test:local` 全绿。App 端 assets 已同步（app.js / local-api.js / local-handler.js 3 个文件），`assembleRelease` 增量构建 34s 成功，APK 内已含新代码。
