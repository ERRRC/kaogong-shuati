# 用户输出风格

本文件只约束用户可见内容；内部仍可使用结构化数据和确定性校验。

## 第一铁律：完整正文直发

- 只要题干与对应材料足以处理，最终消息必须直接包含完整报告正文。
- 禁止用“核心结论速览”“结果摘要”“交付件”“已保存到文件”、文件路径或文件卡片替代正文。
- 文件只能在完整正文之后作为附加产物；不得要求用户打开文件才能看到分析或批改。
- 不因题型、篇幅、客户端模式、是否提供参考答案或考生答案而缩减正文。
- 只有题干或必要材料确实缺失时，才停止解析并一次性说明缺项；不得补造题目或材料。

## 输入组合对应的完整交付

1. 题干＋材料，无考生答案、无参考答案：完整解析，并给出经字数复核的示范答案。
2. 题干＋材料＋参考答案，无考生答案：完整解析，说明参考答案如何参与候选校准、补漏与合并；已有答案不重复照抄，但不得省略材料找点和答案组织。
3. 题干＋材料＋考生答案，无参考答案：完整批改，逐句或逐段诊断，并给出经复核的修改稿或示范答案。
4. 题干＋材料＋考生答案＋参考答案：完整批改，展示校准后的点池、考生覆盖、具体缺口和修复；不得把参考答案当唯一措辞标准。
5. 整卷材料但未指定题目：先完整定位题号、材料、作答与参考答案，列出可处理题目；用户指定后逐题完整输出，不自动把整卷压成主题摘要。

## 各题型的完整度

### 小题与应用文解析

必须包含题干责任、方法步骤、材料原句逐点提取、主点与展开的合并理由、考场组织、易错点，以及规则允许时的完整答案。不能只给答案骨架或四五个关键词。

### 小题与应用文批改

必须先详细拆题，再按考生原句或编号逐条说明：材料依据、命中内容、覆盖状态、具体缺口、影响和直接改法。未写出的核心点也要讲；可选补充不得伪装成硬性漏点。最后给出统一档位、档内位置、建议中心值、区间与置信度。

### 大作文解析

必须包含命题关系与文章责任、方法步骤、全部材料的论据转化、总论点与分论点体系、论证递进、段落组织、易错边界，以及规则允许时的完整范文。不得只发立意、三个分论点和范文标题。

### 大作文批改

必须按自然段点评：段落功能、与总论点关系、材料事实是否准确、是否完成“事实—分析—观点”转化、题干关系是否展开、如何具体修改。最后说明主要失分顺序、保留优点、档位与建议分；不得只给总体评价。

## 参考答案边界

- 有参考答案时必须说明其参与了候选校准，并回材料补漏、合并和复核粒度。
- 参考答案遗漏但材料明确支持的点必须补回；参考答案过拆的子动作不得机械变成硬性核心点。
- 已有参考答案时不重复粘贴整份原文，但完整解析或批改不能因此缩减。
- 无参考答案时按材料独立建点，不降低讲解完整度；不确定性只影响置信度，不允许变成几句泛评。

## 展示边界

- 默认不使用 Markdown 表格，除非用户当前轮明确要求。
- 不展示内部 ID、命令、字段、路径、耗时、日志或工程回执。
- 通过最终校验后，用户消息必须原样等于 `approved_text`；不得再追加工作日志、核心速记、运行结论、技能契约说明或任何工程尾巴。
- 不虚构局部点值，不把建议点值冒充官方扣分细则。
- 方法只写真实加载的中文名称、为什么用、本题怎么用、下次如何复用。
- 最终校验失败只能修正文，不得用摘要绕过；通过后必须逐字发送获准的完整正文。

## 最终文本与字数一致性

- 收尾校验返回的 `approved_text` 是唯一最终正文；通过后禁止再次手工改写、增删或拼接内容。
- 示范答案字数只引用同一份最终回执的实际字数，一份正文只展示一个字数，不同时保留估算值、草稿值和复核值。
- 通过后如果还要修改正文，必须重新收尾校验并以新回执为准；旧回执和旧字数自动失效。
