# 分析内核

本文件定义所有用户模式（审题/解析/批改/对照参考答案/修改二稿/学情报告）共享的数据流与一致性约束。评分内核见 `scoring-core.md`；输入门禁见 `input-boundary.md`；状态引擎见 `state-engine.md`。

批改边界依据见 `scoring-evidence.md`。方法卡只提供操作步骤，不作为阅卷规则或单点分值来源。

**运行流程不在本文件重复定义。** `SKILL.md` 的“普通任务最短执行门禁”是唯一权威运行规则；本文中的“材料、作答、校准”只是同一次入口内的语义检查视图，不代表三次命令、三次建池或三次评分。

整卷 PDF/文档输入默认先走 `paper-analysis` 建卷索引。这个步骤对用户不可见，不是独立用户模式；只保存试卷身份、材料分段、题号、题型、材料范围和参考资料归属。只有用户指定题号或发送可关联的答案后，才为该题建立完整 `analysis-result`。整卷索引不等于逐题解析，也不触发批量评分。

答案卡可以后续单独提供：若能按题号或页面顺序关联，则挂到对应 `question_id`；若整张答案卡包含多道题，则先切分归属，再按用户当前指定题号处理，不要求用户重新上传题面。

## 1. 共享数据流

### 题干深度剖析与答案责任清单

材料阅读前先把完整题干拆成一份“答案责任清单”，不能只凭一个任务动词完成审题。至少核对：

1. **任务动作**：题目要概括、分析、解释、提出、汇报还是论述；它决定答案的基本功能。
2. **作答对象与主体**：回答谁、围绕什么对象、由谁作答；防止把材料主体、考生身份和答案对象混在一起。
3. **材料范围**：限定哪则资料、哪些段落或全部材料；整卷上下文不能自动扩大当前题目范围。
4. **内容组件**：题干明确要求的做法、原因、问题、成效、建议、启示、关系双方等；每个组件都必须在答案中有对应位置。
5. **关系与限定**：如“怎样”“针对”“结合”“分别”“主要”“全面”“成效、不足、建议”等，判断它们是改变答案功能、范围、重点还是组织顺序。
6. **身份、对象、文种和格式**：仅在应用文或题目明确要求时纳入必答结构，不把惯例格式无条件升级为硬要求。
7. **字数、分值和其他限制**：将可见限制转成答案预算；OCR 或题面冲突先标记待核对，不得用常识替换原题。

每个有效题干要素都要转换成一句“答案责任”，例如“概括主要举措”对应“主体＋动作＋对象”，“围绕成效、不足和建议”对应三个内容板块，“怎样实现”对应主体动作和过程机制，结果只能作为必要收束。只有责任清单闭合后，才开始按材料建立点池。

这项清单不是要求用户看到一串工程字段，而是保证解析时每句话都有去处：普通小题的内容句至少承载一个材料主点或关键限定；应用文主体句要落入题目要求的板块并完成文种功能；大作文不要求每句话都单独得分，但每段和每个论证句都必须推进总论点、提供证据、完成分析或回扣，不能用关键词堆砌制造“像答题”的假象。

所有需要理解材料的模式都经过以下共享前置步骤，随后按题型进入唯一内容分支，产出一份 `analysis-result`（JSON，schema 见 `contracts/analysis-result.schema.json`）：

| 步骤 | 产出 | 说明 |
|---|---|---|
| 1. 输入门禁 | 通过/拒绝 | 按 `input-boundary.md` 逐模式检查必需输入 |
| 2. 材料遍 | 段落索引 | 仅基于材料文本，不参考用户作答或参考答案 |
| 3. 任务画像 | task_instruction + constraints | 题型、字数（min_length/max_length/length_unit）、身份、文种、满分、required_format_elements（贯彻执行） |
| 4. 内容分支 | 按题型建立内容证据 | 小题建立 atomic_points[]；应用文建立 application_review 所需的任务要素；大作文建立 essay_review 所需的立意、关系、分论点和论证证据，不建立小题式 scorable point ledger |
| 5. 材料证据索引 | evidence_text | 将各类内容判断关联到原文证据句 |
| 6. 组织与关系 | relationships[] + recommended_structure[] | 小题看点的层次与顺序；应用文看文种结构；大作文看题意关系、分论点体系和论证线 |
| 7. 原型与方法匹配 | prototype_resolution_receipt + method cards | 由当前唯一入口内部完成：解析用 `analyze-once`，批改用 `grade-once`；方法不得修改材料证据 |
| 8. 模式分支 | 按总模式输出 | 题目解析→解析输出并结束；批改后解析→复用解析结果后进入答案对照、评分、诊断和写回 |

内部数据可使用JSON和账本结构，用户展示必须按 `output-style.md` 转成自然语言，不得把内部表格或JSON直接当作默认答复。

## 2. ID 稳定性与复用

- 同一道题（同一材料 + 同一题目要求）的 `analysis_id` 和 `point_id` 在所有模式中必须一致。
- “题目解析”和“批改后解析”是两个总模式，不是两种解析深度：批改必须先完成题目解析所需的完整材料理解，再增加用户答案对照、评分和修复诊断。
- 同一题已有有效 `analysis-result` 时，批改、对照参考答案和修改二稿直接复用该结果；不得重复遍历材料、重新拆分点池或重新路由方法。只有材料、题目要求或题型条件发生变化时才重建。
- 参考资料校准属于当前总模式中的一个步骤，不是独立的第二轮完整解析。只有用户明确要求“对照参考答案”时，才单独输出对比结果。
- 有参考资料时采用参考辅助快速路径：先把参考资料转换为当前题型的候选骨架，再回材料做定向核验、同功能合并和补漏；禁止先完整建立一套细点池、再完整重做一遍参考答案映射。无参考资料时才进行完整独立材料遍。
- 整卷会话中，`paper_id` 是父级上下文，`question_id` 是当前处理单元；每次只加载当前题目所需的 `material_scope` 和参考资料，禁止因整卷材料已存在就重复分析其他题目。
- 解析模式生成的参考答案基于要点池，但参考答案不得反向成为唯一评分标准。
- 解析输出必须保留“逐点材料证据链”：对每个核心点记录材料原句或连续短引文、题目功能、不可丢的实质词和考场压缩表达。参考答案校准只能减少重复遍历，不能用“参考答案已有该点”代替材料证据链。
- 参考资料校准统一区分“有参考答案”和“无参考答案”：有参考答案时以其作为候选骨架，再回材料确认可接受边界和最佳表达；无参考答案时由材料和方法卡独立建立结构。参考答案来源不改变这两条路线。
- 校准参考答案时先判断其是否覆盖题目要求的功能和材料主点，再判断是否有表达精度问题。题干已有的主题词不必机械重复；在严格字数限制下，合理概括“信息传递”“平台服务”等上位表达不得直接判为漏点，除非被压掉的内容承担了独立且不可替代的任务功能。
- 失分标签分三层：`实质遗漏`（独立功能未回答且无等义表达）、`可能弱化`（信息被泛化或限定不够，影响尚不确定）、`表达优化`（主体、动作和功能已覆盖，仅有更准写法）。只有第一层可以直接作为硬失分；后两层必须使用“建议补强/更稳妥”，不能称为“致命硬伤”。
- 方法卡匹配（步骤 7）不得修改材料证据结构——小题方法卡不能新增或删除 `point_id`；应用文和大作文方法卡不能替代题型协议中的任务要素或论证判断。
- 步骤 7 不得由模型凭记忆自行判定题型或命名方法。必须使用当前一次入口返回的真实原型和方法卡 `steps` / `boundaries`；普通任务不得再拆成底层 `resolve-*` 命令。
- 原型解析优先使用字面触发；字面未命中时可使用引擎确定性的任务功能语义兜底。用户可见结果不展示内部字段，但内部必须保留解析模式和依据；兜底无法排除多个任务功能时，仍应停止并提示题干歧义。
- 若路由解析、卡片加载或适用性校验失败，停止当前模式并报告“方法库加载失败”；不得静默退化为模型自由发挥。
- 方法卡调用必须体现为 `analyze-once` 或 `grade-once` 的实际回执；参考答案成稿的字数必须有 `check-word-count` 回执。仅用文字声称不构成通过。
- 字数门禁采用统一的“实际字符数”口径：去除换行和 Markdown 外壳后，标点占用字符也计入长度；标点不参与内容得分、证据匹配或表达质量判断。字数回执必须说明该口径。
- 输入内容（材料、题目要求）变化后必须生成新的 `analysis_id`，不得沿用旧 ID 的分析结果。
- `analysis_id` 由材料哈希 + 题目要求哈希派生，确保同一题多次分析得到同一 ID。

## 3. 解析产出规则

“题目解析”模式和“批改后解析”模式都必须产出可迁移解释，具体规则见 `references/explanation-core.md`。批改后的解析深度不得低于题目解析；它还要增加“考生写了什么、漏了什么、为什么影响得分、下一次怎么改”。原子要点不能只保存“点文本和材料证据”；用户可见解析还必须逐点展示“材料原句→功能判断→不可丢词→压缩表达”，并说明该点如何回应题目。评分是诊断的结果，不是解析的替代品。

## 4. 模式分支规则

| 模式 | 复用 analysis-result | 额外输入 | 额外产出 |
|---|---|---|---|
| 审题 | 是（步骤 1-8） | 无 | 题型/任务限制/材料结构/原子要点/得分点 |
| 题目解析 | 是（共享前置+题型分支） | 无用户作答 | 审题关键词/逻辑/要点优先级/方法卡/作答框架/易错点 |
| 批改后解析 | 是（复用题目解析） | 用户作答 | 在完整解析基础上增加答案对照/评分/失分/修改清单/局部示范 |
| 对照参考答案 | 是（复用题目解析） | 参考资料；若同时有用户作答则复用批改结果 | 等义比对/校准/偏差分析；不重复跑完整解析 |
| 修改二稿 | 是（同一 analysis_id） | 一稿 + 二稿 | 改善/退步/残留/分数变化 |
| 学情报告 | 否（读 SQLite） | 无 | 题型分布/维度表现/常见遗漏/二稿改善/方法掌握 |

## 5. 与评分内核的关系

- `analysis-result` 是评分的输入之一：`scoring-input`（见 `contracts/scoring-input.schema.json`）引用 `analysis_id`，并携带用户作答、维度等级、要点映射。
- 评分公式严格按 `scoring-core.md` 执行，本文件不定义任何评分算术。
- 正式评分必须同时通过语义门禁（`input-boundary.md`）和 `grade-once` 内部的确定性校验。

## 6. 与方法库的关系

- 方法卡通过 `method_card_ids` 字段关联到分析结果，但方法卡不参与要点提取。
- `method_card_ids` 只能引用 `sl-card-*` 格式的正式卡 ID，`uniqueItems=true`，`maxItems=5`。
- 方法选择必须发生在对应题型的材料证据结构建立之后（步骤 7），不得反向修改小题要点池、应用文任务要素或大作文论证判断。
- 方法卡的 `影响评分维度` 字段用于诊断建议，不得用于修改维度权重或层级。
- 审题、解析、批改、二稿必须复用同一 `analysis_id` 和 `point_id`。
- 学情报告记录方法使用情况时只能写真实调用过的 `card_id`。
- 方法卡必须真实存在、无重复、总数≤5、题型与模式适配，且符合能力内核≤1、题型工作流≤3、批改二稿≤1的预算。该校验由当前一次入口内部完成；普通任务不再额外调用 `validate-method-selection`。

## 7. 完整性与争议处理

- `completeness.status` 为 `incomplete` 或 `uncertain` 时，不得进入正式评分（批改模式）。
- `disputes[]` 记录等义争议、多种合理分类、参考答案冲突等；低置信度时按 `scoring-core.md` 置信区间展宽规则处理。

## 8. 字数门禁与格式要素一致性

- 审题阶段必须在 `constraints` 写入 `min_length`/`max_length`/`length_unit`（详见 `scoring-core.md` 字数门禁）。
- 解析参考答案、批改用户作答、二稿用户作答均须过字数门禁；超限/不足不得评完全合规。
- 贯彻执行题审题必须在 `constraints.required_format_elements` 写入必需要素；批改只允许对缺失的必需要素扣 `身份文种格式` 分；审题与批改 `required_format_elements` 不一致必须校验失败（详见 `scoring-core.md` 必需格式要素规则）。

### 解析参考答案的一次成稿流程

1. 先把题面上限转成作答预算：默认以上限的 85%–95% 为内部规划区间，为标点、调整和方格布局留余量。该比例是训练建议，不是全国统一的官方评分档位或扣分公式。
2. 从原子要点中建立“必保留证据词”清单：优先保留主体、动作、对象、特色做法和关键限定，不用空泛上位词替换可得分的材料细节。
3. 先分配每个任务组件的字数，再一次成稿；不得先写严重超限稿，再靠大幅删减补救。
4. 超限时的压缩顺序：删重复修饰和空话→合并同义动作→压缩连接词→最后才评估次要细节。不得先删非遗、民俗、合作主体等能区分得分点的证据词。
5. 输出前必须运行字数门禁；未通过的草稿不得展示为“参考答案第一版”。

### 解析中的材料逻辑复核

**文字核验边界**：材料点池和证据回查只复核文字内容，不把标点、引号、顿号、括号、破折号、空格、换行或 OCR 排版差异当作内容错误。机器匹配允许这些形式差异；但不能因此忽略主体、动作、对象、数量、限定词或因果词等实质文字差异。应用文的格式评分、大作文的结构评分仍按各自题型协议单独处理，不能与材料证据核验混为一谈。

解析不能把“找到了若干关键词”直接等同于“找准了得分点”。正式解析在生成参考答案前，必须对每个拟列为核心点的内容做一次轻量复核：

1. **任务对应**：它是否直接回应题目要求，而不是材料中的背景、例子或泛泛意义。
2. **原文依据**：能否定位到明确材料句；规范化表达可以提炼，但关键主体、动作、对象、结果和限定词不得无依据替换。
3. **独立性**：与相邻点是否存在同义重复；如果只是同一事实的例子、效果或限定信息，应挂在上位点下，不另列硬得分点。
4. **层次与顺序**：合并要看主体是否一致、段落是否相邻、侧重点是否相同；拆分要看是否存在独立动作、独立结果或题目要求的不同层次。不得为了凑点数把原文的 1、2、3、4 强行拼成 1、3、5。
5. **证据等级**：明确材料原句是硬依据；由材料直接归纳的是稳健依据；仅凭常识或阅卷经验推导的是可选解释，不得直接变成必答点。

解析展示时把内容分成“核心得分点”“展开/限定信息”“背景或例子”三类。没有官方评分细则或多份答案交叉支持时，使用“核心得分点/候选点”表述，不虚构单点分值和确定性扣分阈值。

点池允许记录 `review_status=confirmed/candidate/disputed`。candidate 或 disputed 点可以用于解释材料线索，但不得直接作为确定性遗漏、硬扣分点或高档门槛。OCR/转录疑点统一写入 `ocr_issues`；未解决疑点不得作为确定性证据。

对“机制总括词”与“落地动作链”要分层：只有会改变机制是否真正成立的限定才写入 `critical_qualifiers`。例如联合治理不仅是“建立联合河长办”，还可能要求方案编制、联动实施和闭环落实；若用户只写前者，解析应明确说明“方向命中、落地链条不完整”，不得把普通展开细节无限拆成新得分点。

### 参考资料对比的吸收规则

有多份参考资料时，不按“出现次数最多”机械定论，而是分四步处理：先找共同核心点，再审查单独出现的内容是否有材料依据，再舍弃材料外或破坏原文逻辑的内容，最后按题目设问重新组织。小题参考答案可用于校准要点；大作文范文、立意解析、评语和分数只能用于校准题意、论证方向和档位边界，不得直接替代独立分析。

材料原词和考生概括不是二选一：主体、动作、对象、关键限定优先保留材料原词；材料零散时允许使用自己的上位概括，但概括必须能统领后文，不能用空泛词替换可得分细节。

### 有参考资料的快速解析分流

参考资料存在时只保留一次内容编译，按题型执行：

1. **归纳概括、综合分析、提出对策**：把参考答案分条转成候选主点，回材料核验依据；合并同功能内容，补入参考答案遗漏但材料明确支持的独立主点。参考答案的动作、例子和效果默认作为主点展开。
2. **贯彻执行**：把参考稿转换为身份、对象、目的、文种功能、内容板块和成效候选，再回材料补漏。允许合理格式和组织变体，不按参考稿字面顺序判错。
3. **申发论述**：参考立意、范文和评语只生成候选立意、关系处理、材料运用和论证线；必须回到题干和材料核验，不复刻范文分论点，不输出唯一标准结构。

快速路径仍必须检查参考资料是否对应当前题目、每个候选是否有材料依据，以及材料是否存在参考资料未吸收的重要内容。它减少重复分析，不降低证据要求。

## 9. 要点粒度规则（跨模式统一）

原子要点的拆分与合并直接影响覆盖统计和评分可比性。以下规则跨模式统一执行：

1. **最低单位**：原子要点以"可独立判断覆盖、具有独立材料依据"为最低单位。
2. **可合并**：同一主体、同一动作、同一对象且仅为同义展开的表述，可合并为一个要点。
3. **不得合并**：主体、动作、对象、结果或逻辑功能不同的信息，原则上不得随意合并。合并后会导致其中一个子项无法独立判断覆盖状态时，必须拆分。
4. **上位不自动覆盖下位**：上位概括不得自动覆盖可独立得分的子要点。用户只写上位概括时，未写出的独立子要点仍标为"未覆盖"。
5. **限定信息不拆分**：同一事实的数字、例子和解释通常作为该要点的限定信息，不自动拆成独立要点。仅当数字/例子本身是独立得分信息（如题目要求列举具体数据）时才拆分。
6. **跨轮语义可映射**：三轮评分允许措辞和编号不同，但语义颗粒必须可映射。要点池建立后，若后续轮次发现可合并/可拆分争议，记录在 `disputes[]` 中并标注两种口径。
7. **拆分争议处理**：要点存在合理拆分争议时：
   - 并列记录两种口径（`disputes[]` 中写明粗粒度口径和细粒度口径）
   - 采用较宽分数区间（置信度降为低）
   - 不因拆分数量差异直接改变覆盖档位（如粗粒度覆盖 6/7 与细粒度覆盖 8/12 语义等价时，要点覆盖层级应一致）
8. **独立得分四问**：只有同时满足“直接回应题干任务、有可定位的材料证据、与已有要点语义不重复、可独立判断用户是否覆盖”时，才可设为 `independent_scoring: true`。任一问不满足，就应作为已有要点的限定、证据、例子或背景，而不是新建得分点。
9. **例子与子应用默认不独立**：某一概念的具体系统、场景、试验基地、工具或应用效果，若只是证明或展开上位概念，应挂在该概念要点下，不得再算一个遗漏点。
10. **背景与政策语句按任务过滤**：题干未要求背景、意义、必要性或政策依据时，宏观背景和权威论述不得自动列为必答点；它们可用于理解材料或组织表达。
11. **推导关系不冒充材料关系**：因果、反馈、输入输出或闭环关系必须由材料明示语句或两条可直接衔接的证据支持。合理但未明示的推断只能进入 `disputes[]` 或作为可选解释，不得作为必答得分点。关系逻辑评分只能引用 `analysis-result.relationships` 中存在的关系，且关系两端 point_id 真实存在且有明确材料证据或被标为 `required`。不得要求用户补写材料未明确的数据流、反馈链或闭环。可推断关系只能标记为 `disputed`/`optional`，不得成为扣分依据。
12. **禁止从用户答案反推要点**：要点池必须在查看用户作答前由材料和题干建立。用户作答中出现而材料无法定位的枚举、概念或关系，只能标记为材料外内容或待核对争议，不得回填进原子要点池。
13. **scorable_point 硬约束**：只有满足 `status=="active" && independent_scoring==true && required_or_optional!="optional"` 的点才算可评分点，进入正式覆盖统计和要点覆盖档位。非独立/可选点只作证据补充，不得称为遗漏或影响分数。
14. **关系验证通用化（v0.3+）**：每条关系必须有稳定 `relationship_id`。`user_output_plan` 中所有关系主张必须引用真实 `relationship_id`。`relationship_id` 不存在、方向不符或引用已排除 point 时必须失败。不允许根据出现特定词组猜测关系合法性。不修改材料要点，不制造材料外关系。
